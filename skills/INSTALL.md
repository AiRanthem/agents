# 全局 Skills 安装与更新

本目录保存所有公共技能，包括维护本 dev-kit 的 `install` 和 `absorb-skill`。每个技能的完整目录以独立绝对软链接安装到 `~/.agents/skills/<name>`，入口、引用、脚本与模板通过同一目录访问。宿主专属技能由调用方提供的相应安装契约处理。

## 安装

1. 从安装技能的实际路径定位 dev-kit 根目录，读取其 `AGENTS.md`，核对共享技能与安装目标。首次安装可直接读取本仓库的[安装入口](install/SKILL.md)。
2. 使用 `find skills -mindepth 2 -maxdepth 2 -name SKILL.md` 发现并验证仓库中的每个 skill，确保 `~/.agents/skills` 存在。skill 名为含 `SKILL.md` 的目录名，且须与 frontmatter `name` 一致。
3. 对每个 skill，将空闲的 `~/.agents/skills/<name>` 安装为指向仓库 `skills/<name>` 的绝对软链接。校正可确认指向本仓库的旧链接。遇到同名外部软链接、普通文件或目录，展示目标或相关差异并取得用户决定后替换。继续同步其他无冲突的条目。
4. 只清理可确认指向本仓库 `skills/` 内已移除 skill 的链接。检查失效链接时用原始链接目标和链接所在目录确定目标路径。保留归属不明的条目和其他文件、目录及软链接。
5. 核对下文的软链接验证项。重启当前 Agent 后使用其技能列表确认结果。

## 更新

仓库更新后重新执行安装流程。新增 skill 必须补齐对应软链接；删除 skill 必须移除对应软链接。不得留下指向本仓库、但已无对应 skill 的用户级链接。

## 第三方技能接管

先让仓库内替代技能可审阅并通过验证，再检查原目录、调用策略与来源元数据。第三方普通目录不属于第 4 步的仓库软链接清理范围；取得迁移授权后，将指定原目录完整备份到技能发现路径之外，再验证旧版不再被发现。低价值技能可以不吸收；停用其现存安装仍须在授权范围内。

## 验证

确认以下结果：

* 对每个公共技能，`~/.agents/skills/<name>` 都是指向本仓库对应 `skills/<name>/` 完整目录的绝对软链接，入口和配套资源可以通过该路径读取。
* 本仓库管理的已删除 skill 软链接已移除。
* `~/.agents/skills` 中与本仓库无关的条目未被改动。
