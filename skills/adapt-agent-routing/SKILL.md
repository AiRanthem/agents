# Adapt agent routing

Decide which assignments the lead should do directly and which model and reasoning level should own each worthwhile delegation. Optimize cost and elapsed time per accepted result at the required quality. An analysis request ends with concrete proposed edits. Apply changes when the user requests implementation.

**Establish the baseline.** Trace the active policy from its entry points to the instructions each role actually receives. Record available profiles, user-selected roles, permission boundaries and who owns final judgment. Separate a model family that selects a policy from the models the policy recommends as executors.

**Compare current evidence.** Date and link the provider's model and price documentation and the benchmark publisher's original results. Compare incumbents and candidates at named reasoning levels on the same harness, version and task mix. Look at implementation, terminal work, repository questions and independent judgment separately. Keep the general ability index, benchmark task cost, elapsed time and token rates in their original units. Mark unmeasured levels and incompatible suites explicitly.

**Check representative work.** When authorized local history is available, choose a bounded window and classify tasks from their assignments before examining answers. Include routine work, ambiguous cases, failures and corrections. For routing comparisons, verify which choices the lead could make under the original assignment and compare like tasks. Inspect source references, parent reuse or corrections, independent checks and follow-up work for the cases that could change the decision. Report sample sizes and unknown outcomes. First-turn completion measures a handoff. Quality and acceptance need their own evidence.

Use observed token categories and the applicable price tier for any currency estimate. Label fixed-token repricing as a counterfactual. Changing model or reasoning level can change token use, latency, verification and rework. For a matched execution comparison, use identical inputs, tools, acceptance criteria and agreed cost limits. Local histories and raw work products stay within their authorized scope.

**Decide and verify.** For each material change, give the assignment, old and proposed route, reason and uncertainty. Consider direct execution, merging redundant rules, cheaper bounded work and targeted independent judgment. Resolve contradictory signals with the task-specific evidence. Replay the proposed policy on representative assignments and event boundaries, including an unknown model and a restricted role. For implementation, update the policy's owner and affected checks, then verify the installed entry and effective instructions. Report separately what the harness loaded and what real agents executed.
