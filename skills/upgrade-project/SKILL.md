# Upgrade Project

Use the selected management root and the project entrypoint resolved by the [command contract](../manage-workitems/references/commands.md) for `--root PROJECT migrate`. Only when the user requests a preview, use `migrate --dry-run`. The program performs schema migration and generated entrypoint reconciliation; do not hand-edit generated entrypoints or YAML, construct JSON mutations or manually publish Git/Aone state.

The program preserves work-item IDs, dependencies, ownership and current pointer-bound evidence. Upgrade projects with active owners through the same deterministic migration, preserving their existing claims and authorizations. It generates the current root/item entrypoints and routes current business constraints through `.project/project-instructions.md`, current context and required original main-workspace instructions. Project documents contain current effective content only; Git history records prior versions. Knowledge metadata moves from JSON to YAML with its fields and Markdown body preserved, while the body remains opaque. A project-specific permission, business or delivery boundary cannot be discarded because a generic template omits it.

An unknown/custom instruction source or unresolved backend operation is a concrete blocker. If migration returns `code: current-instructions-required` or `unsupported-custom-instructions` with `read_sources`, read those sources and any other relevant original documents to organize their still-effective constraints into complete current Markdown. Supply the result with `migrate --instructions-file PATH`; do not copy historical prompts or splice raw legacy documents into project content. Reuse existing user-maintained authority and approval for the same business scope; do not routinely ask for reapproval. If a real business change or permission is unknown, report that specific gap and ask only for the missing information. The program does not interpret Markdown semantics or identify obsolete sections. Migration does not approve a design, establish independent review, take over a writer or authorize code submission.

Follow the returned status exactly: `published` reports verified completion; `migrate` returning `no_op` reports that current content needs no update. `partial` retains the original migration operation, intended paths, validation result and exact resume command; continue that operation through the returned command. For `status: blocked` with `code: stale_ticket`, execute only the returned `next_command`, while `status: blocked` with `code: stale_evidence` has no continuation command and requires current authorization/review evidence. Other blockers or missing facts are reported and stop the affected operation.

A `resume` result of `no_op` establishes only that recovery performed no operation. When the original migration had pending changes, establish that those changes were published, completed by an equivalent operation, or remain incomplete. If recovery returns only an empty `no_op`, run the project program's authoritative `status` command to reconcile the original transaction. Follow any pending transaction's returned recovery command. Once the program confirms there is no pending transaction, rerun the still-authorized `migrate` to finish the update or establish that current content needs no change. Preserve the original intent across this check; validation success and an empty recovery `no_op` alone cannot establish completion. Source/content hashes make repeats stable, without timestamp edits or empty commits. Use program-reported transaction and remote evidence for these checks.

Report the source identity, changed paths and current constraints carried forward. State separately whether updates were needed, whether they reached the local checkout, whether a commit was created and pushed, and whether the remote was verified. Distinguish incomplete or unknown outcomes from completed publication using the original migration's evidence. Installation of shared skills, code migration, main-workspace publication, worktree moves and remote deletion remain outside this operation's authorization.
