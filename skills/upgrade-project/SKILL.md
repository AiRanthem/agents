# Upgrade Project

Read the selected project's instructions, configuration, work items and business context, then compare them with the current [project layout](../manage-workitems/references/schema.md) and [workspace template](../create-project/assets/workspace/AGENTS.md). Edit the existing files directly under the user's upgrade authorization. A requested preview remains read-only.

Preserve stable IDs, dependency relationships, source locations, actual user decisions, substantive author/reviewer attribution and current review, acceptance and delivery evidence. Consolidate instructions into current effective content; Git history preserves earlier versions. Remove obsolete command routing, process-only metadata and bypass rules when they have no remaining business purpose. Do not discard project-specific constraints merely because a generic template omits them.

Read original business instructions and retain their meaning. Reuse existing authorization for unchanged scope. If a consequential business choice is genuinely unknown, ask only for that choice while completing independent updates. Preserve unpublished source, reports and data needed to understand uncertain external outcomes; upgrading instructions does not authorize source publication, worktree moves or deletion of remote resources.

Check edited documents and configuration for coherent paths, references and retained facts. Commit project changes and push the configured branch. Report changed paths, preserved constraints, actual publication outcome and unresolved external synchronization. Identical current content needs no empty commit.
