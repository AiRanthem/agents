# Upgrade Project

Use the selected management root and installed `manage-workitems/scripts/project.py --root PROJECT migrate`. Only when the user requests a preview, use `migrate --dry-run`. The program performs schema migration and generated entrypoint reconciliation; do not hand-edit generated entrypoints or YAML, choose input documents outside returned `read_sources`, construct JSON mutations or manually publish Git/Aone state.

The program preserves work-item IDs, dependencies, ownership and current pointer-bound evidence. It generates the current root/item entrypoints and routes current business constraints through `.project/project-instructions.md`, current context and required original main-workspace instructions. Project documents contain current effective content only; Git history records prior versions. Knowledge metadata moves from JSON to YAML with its fields and Markdown body preserved, while the body remains opaque. A project-specific permission, business or delivery boundary cannot be discarded because a generic template omits it.

An unknown/custom instruction source, active ownership or unresolved backend operation is a concrete blocker. If migration returns `code: current-instructions-required` or `unsupported-custom-instructions` with `read_sources`, read those exact sources and organize their still-effective constraints into complete current Markdown. Supply the result with `migrate --instructions-file PATH`; do not copy historical prompts or splice raw legacy documents into project content. Reuse existing user-maintained authority and approval for the same business scope; do not routinely ask for reapproval. If a real business change or permission is unknown, report that specific gap and ask only for the missing information. The program does not interpret Markdown semantics or identify obsolete sections. Migration does not approve a design, establish independent review, take over a writer or authorize code submission.

Follow the returned status exactly: `published` reports completion; `no_op` reports already current without churn; `partial` permits only the returned resume command; for `status: blocked` with `code: stale_ticket`, execute only the returned `next_command`, while `status: blocked` with `code: stale_evidence` has no continuation command and requires current authorization/review evidence. Other blockers or missing facts are reported and stop the affected operation. Source/content hashes make repeats stable, without timestamp edits or empty commits. Do not run additional Git/Aone checks or choose another recovery path.

Report the source identity, changed paths, current constraints carried forward and actual migration/publication result supplied by the program. Installation of shared skills, code migration, main-workspace publication, worktree moves and remote deletion remain outside this operation's authorization.
