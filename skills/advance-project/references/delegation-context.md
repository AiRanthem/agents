# Prepare shared context before delegation

Use this guidance for authorized multi-agent work, including ordinary skill execution. It does not start an autonomous project or change roles, permissions or independence gates.

Before dispatch, reuse current reads and inspect the smallest set of original material that the lead and descendants are likely to read repeatedly: applicable instructions, the complete relevant contract, stable target/diff, and central interfaces, callers or test oracles. Read actual content, not only paths or summaries. Bind it to source locations and the current artifact identity. Stop when the likely shared working set is covered; leave specialist-only exploration to its owner. Do not preload the repository or delay useful parallel work for speculative cache hits.

Prefer a full fork when the host preserves the shared history prefix, the shared material is substantial, parent and child use the same model and effort, the inherited history is relevant, and required role instructions, permission boundaries and independent judgment remain valid. Otherwise use clean dispatch. Read the shared material before forking, keep that prefix unchanged, and append the descendant's scope and remaining gap afterward. Do not copy the same material again into the task. Inherited controller or routing text does not assign the child those responsibilities. Fixed first-level project roles continue to use the host adapter's clean-context dispatch.

Use a clean context when changing model/effort, inheriting unrelated history, or when a reviewer's inherited history would include implementation, rebase, draft authorship, substantive design revision or prior review judgments. A review lead independent of those activities may fork its primary-material context to a quality reviewer or specialist before forming findings; do not include prior verdicts or author deliberations. An author's full-history fork cannot establish independent review. If the host cannot preserve the necessary boundaries, use clean dispatch with the complete required original inputs and a compact evidence index. Keep any shared original text byte-stable and before task-specific instructions; summaries remain navigation. Do not change model routing merely to share a cache.

Inherited current primary material need not be reread only to repeat a tool call. Re-read changed or missing inputs and honor mandatory instruction reloads; each reviewer still examines the critical code and test oracles and forms its own judgment.

Cache reuse requires a matching rendered prefix and compatible request settings, not merely identical file contents. Parent-only reads do not transfer a history prefix to a clean child. Report savings only from actual usage evidence, including cached/uncached input, cache writes where exposed, latency and total work. See [OpenAI Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching).
