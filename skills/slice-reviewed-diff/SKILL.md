# 将大型 diff 分片合入

每轮推进一个可独立合入的小 PR。只读咨询只给判断。执行切片时先定位原开发树、开发分支、目标上游及当前轮次。已有切片则从其工作树、评审快照或 PR 继续；若用户撤回未合入的切片，保留工作树和引用，记录未交付范围。

## 1. 分析并创建切片分支和工作树

以目标上游为基线，分析原开发分支的独有提交、工作目录中的全部变更及相关未跟踪文件。按代码实际依赖选择最底层可独立合入的一项行为，把必须一起变更的定义、调用方、测试和文档划入同一片。必要前置若仍在开发分支中，先评估该前置能否独立成片。

从最新目标上游创建独立分支和工作树，按块从原开发树的当前内容提取该片，同文件中的其他任务留在原树。核对切片相对上游的完整差异，运行覆盖该行为的最小可执行检查。例如，迁移共享定义时，应查清包内和跨包的所有引用，并验证全部受影响的包。

## 2. 用户阅读切片工作树

交给用户阅读前，固定上游基线、原树中本片的来源版本和切片初始快照，覆盖本片新增、修改及删除的内容。每片提取完成后，在给用户的回复中列出该切片工作树的绝对路径、分支、切片目标和相对基线的完整 diff。用户在切片工作树中阅读和修改；需要阅读导航时，对这份切片 diff 使用 [diff-reading-order](../diff-reading-order/SKILL.md)。用户确认读完时，记录其确认的最终切片版本，作为回写和创建 PR 的依据。

## 3. 检查快照，回写原树并创建 PR

评审中有修改时，将切片工作树的当前内容与初始快照比对，覆盖本片新增、修改和删除的文件。逐块将采纳的修改回写原开发工作目录。对照提取时的来源版本与原树现状，跳过已有的等价修改，保留用户后续编辑。遇到无法兼容的重叠修改，保留两边版本并指出冲突块，待用户决定后继续。

创建 PR 前再次核对快照，确认原树已包含采纳的修改，完整切片与用户读完的版本一致，并验证最终切片。若验证引入新修改，在切片树中请用户补读受影响的部分，再次核对和回写。按授权提交、推送并创建 PR，交接工作树路径、分支、提交 SHA、PR 链接、验证及回写结果。

## 4. PR 合入后 rebase 原开发树，缩小剩余 diff

fetch 目标上游，核实 PR 的实际合入结果及对应提交已包含在目标历史中。squash 或 rebase 合入时使用上游实际产生的提交；核对最终 diff、评审期间的修改及后续 revert。PR 关闭、切片分支存在或本地测试通过，都不足以启动本轮合入后的同步。

1. 固定原分支 HEAD，保存可恢复的工作目录快照，覆盖文件内容、模式、删除及未跟踪文件。按仓库已有的恢复流程，将开发分支 rebase 到固定的最新上游。原分支没有独有提交时可快进。改动大面积重叠时，先在隔离副本验证恢复。
2. 确认目标上游已是开发分支祖先。对照快照和实际合入的 PR，逐块确认已合入的改动退出剩余 diff，同文件中的其他改动及未跟踪文件仍完整。PR 最终实现与原树有差异时，保留仍需迁移的部分，将新写的冲突解法交给用户阅读。遇到并发编辑或无法确定取舍时，保留恢复快照，指出具体差异。记录 PR、实际合入 SHA 和同步后的开发 HEAD。
3. 同步验证通过后、选择下一片前，按 [cleanup-worktree](../cleanup-worktree/SKILL.md) 清理已合入切片的独立工作树。核对工作树干净且提交可从保留的远端引用恢复，移除后确认目录和 Git 工作树登记均已消失，并在本轮交接中记录清理结果。若有待保存的内容或无法证明可恢复，保留该树并记录原因。清理范围限于该切片工作树，分支和恢复引用的删除按单独授权处理。清理完成后按依赖选择下一项完整任务，直到约定范围全部合入。
