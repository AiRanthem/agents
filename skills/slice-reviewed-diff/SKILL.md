# 按人工审查进度切片

同一项重构一次只推进一个可独立合入的小 PR。用户在原开发工作树边读边改，用暂存区标记已经认可的版本，并负责推进 PR。只读咨询只给判断。用户委托按本流程执行时，完整已审切片直接提交。推送、创建 PR 和合入分别遵循用户授权。

## 找到当前轮次

确认原开发树、开发分支、目标上游（通常为 `upstream/master`）及当前切片的 PR 状态。已提交的切片按现有授权推进。合入后，同步开发树、核对暂存区并清理切片工作树，再选下一片。若用户明确撤回尚未合入的切片，记录未交付范围，保留工作树和引用，从约定的剩余范围重新选片。恢复未提交候选时，以当前上游和原开发树的暂存块重新选片。

只读检查原树的 `git diff --cached`、`git diff`、相关未跟踪文件及尚未进入主干的提交，用于理解完整任务和依赖。唯一可提取的来源是用户在原开发树中暂存的具体代码块，以 `git diff --cached` 核实。用户自行审阅和暂存；同一文件中的后续编辑和其他切片须逐块区分。

## 按依赖选择一个切片

每个 PR 交付一项完整任务。先用一句话写出合入后应成立的结果，在目标上游查清定义、所有受影响的生产调用方、测试和仍指导使用的文档，据此划定范围。整片所需改动均已暂存，才可创建切片分支或工作树、提取和提交。

例如，迁移共享日志级别 `DebugLogLevel` 时，完成条件是仓库只有一个正式定义，全部调用方使用新定义。应从旧定义查起，覆盖跨包引用、定义所在包内的裸引用以及测试。只迁移 cache 的等待器和控制器时，即使两包测试通过，只要其他包仍引用旧定义，整项仍待补齐。用同一组检查验证切片前后的差异：在目标上游和候选树分别清点旧定义及引用，再编译候选树上所有受影响的包并运行相关测试。

以当前上游为起点，沿接口、实现、调用者、数据格式和测试查清：单独应用这个改动时，哪些前置还缺失，哪些调用者必须一起迁移。把必须原子变更的内容并为一片。优先无未合入前置、被后续切片依赖的最小完整行为；几个独立候选同样可行时，先取已全部暂存的，再取只差少量阅读的。用一个真实调用或契约解释先后顺序。用户修改底层实现后，重查受影响的上层和原阅读范围。

| 本轮状态 | 动作 |
| --- | --- |
| 有可独立合入且完整已审的切片 | 从最新上游新建独立分支和工作树。只提取原 index 中属于该片的改动，在该基线上验证并提交。原开发树和其 index 保留。 |
| 必要前置只在开发分支已有提交中，目标上游仍缺少相应行为 | 指出前置提交及依赖它的调用或契约，继续评估其他独立候选。若均受阻，报告所缺前置，待上游具备该行为后重新选片。 |
| 前置已满足，选定任务仍有待审或待补的改动 | 在原开发树用 [diff-reading-order](../diff-reading-order/SKILL.md) 生成阅读顺序。传入切片目标、待审代码块，以及为达成目标尚需修改的调用点或测试。已审依赖仅作上下文。用户按导航审阅、修改并自行暂存。 |

用户确认暂存后，从当时的上游和原开发树重新评估依赖顺序、整片范围及每个必需代码块的暂存版本。若底层接口或实现已改变，沿新调用链重新确定调用方和测试；新的最底层完整任务可以取代上次候选。仍有缺口就交回新的阅读范围。

## 从已审版本生成提交

固定候选的开发 HEAD、相关 index blob 或暂存补丁，以及上游基线。使用 `git diff --cached --binary` 或 `git show :<path>` 取得已审版本；混合文件按代码块提取。把选中补丁应用到切片树，保留新版上游在同文件的其他修改。提交前对比切片树相对固定上游的**完整差异**与选中的已审块，并运行覆盖该行为的最小可执行检查。

若移植、冲突处理或验证发现需要新增逻辑、测试或接口适配，停止提取和提交，回到上述待审流程，为受影响的代码更新阅读顺序。待用户在原开发树完成暂存后重新评估。提交前再次核对当前暂存块与切片完整差异；如同一处出现影响任务的新编辑，回到选片和暂存核对。

交接切片树路径、分支、基线、提交 SHA、验证结果和等待用户推进的 PR。在已有工作项或双方约定的交接位置保存该轮事实；普通仓库可交还一行含原分支、切片分支及 SHA 的恢复信息。若下次有多个可能的历史切片，通过这行信息或 PR 定位后再同步。用户继续阅读其他代码时，以届时的 index 为准。

## 合入后同步开发树

fetch 目标上游，核实 PR 的实际合入结果及对应提交已包含在目标历史中。squash 或 rebase 合入时使用上游实际产生的提交；核对最终 diff、评审期间的修改及后续 revert。PR 关闭、切片分支存在或本地测试通过，都不足以启动本轮合入后的同步。

1. 固定原分支 HEAD 和已提交的重放范围。在触碰开发树前，保存可恢复的 index tree、工作目录内容和未跟踪文件；用树或 blob 身份核对内容和文件模式。保留同文件的部分暂存、删除、新文件及无关资产。遇到普通 tree 无法表示的 index 状态，先验证专门的恢复方式。保留恢复引用到同步完成并验证，发生并发编辑时重新取证。
2. 将开发分支 rebase 到固定的最新上游；原分支没有独有提交时可快进。按仓库已有的 rebase 恢复流程处理。对于大面积重叠或部分暂存的现场，先在隔离副本验证重放和恢复，再更新开发树。分别核对已审层（旧 HEAD 到 index）和后续编辑（index 到工作目录），单独核对未跟踪文件。仅凭 `--autostash` 无法证明这三者恢复正确。
3. 已等价合入的代码块退出剩余 diff。同文件里其他已审块仍暂存，后续编辑仍待审。PR 最终实现与原树有差异时，核对用户意图与最终行为，保留仍需迁移的部分；新写的冲突解法单独标记待审。若无法安全还原审查边界或有业务取舍，保留可恢复状态，指出具体差异再由用户决定。
4. 核实目标上游已是开发分支祖先。对照恢复快照逐块检查 `git diff --cached`（哪些已审块被上游吸收、哪些仍暂存）及 `git diff`（后续编辑仍未暂存），核对未跟踪内容和相关行为。即使最终文件字节完全相同，也要验证两层差异。记录 PR、实际合入 SHA 和同步后的开发 HEAD。
5. 同步验证通过后、选择下一片前，按 [cleanup-worktree](../cleanup-worktree/SKILL.md) 清理已合入切片的独立工作树。核对工作树干净且提交可从保留的远端引用恢复，移除后确认目录和 Git 工作树登记均已消失，并在本轮交接中记录清理结果。若有待保存的内容或无法证明可恢复，保留该树并记录原因。清理范围限于该切片工作树，分支和恢复引用的删除按单独授权处理。 清理完成后按依赖选择下一项完整任务，直到约定范围全部合入。
