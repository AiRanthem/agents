# 将大型 diff 分片合入

只读咨询只给判断。执行切片时先定位原开发树、开发分支、目标上游及已有切片。当前切片尚未创建 PR 时，从其工作树和已有评审快照继续。确认该片 PR 已创建，即可在约定范围内提取下一片。原开发树的同步和工作树清理按实际合入情况另行处理。

## 1. 分析并创建切片分支和工作树

分析原开发分支的独有提交、工作目录中的全部变更及相关未跟踪文件。对照最新目标上游和各开放 PR 的当前 diff，按行为和改动块排除已在上游或已有 PR 覆盖的部分。同一文件中的独立改动仍可选。切片撤回或 PR 关闭未合入时，保留工作树和引用，将仍属约定范围的未交付改动重新纳入候选。

选择能在最新目标上游独立合入并验收的一项完整行为或迁移。沿实际生产入口追到改动处，说明这片单独合入后能验证的结果。把必须一起变更的定义、调用方、测试和文档划入同一片。只有后续接线才会用到的改动，默认和首个生产调用方一起切。若要单独切出前置，说明它现在可独立验收的收益，以及分开交付的理由。

若必要前置尚未切片，先评估它能否独立成片。若前置已在开放 PR 中，优先切其他独立任务。剩余任务都受阻时，指出所依赖的 PR。前置进入目标上游后即可选取依赖它的任务。

从最新目标上游创建独立分支和工作树，按块从原开发树的当前内容提取该片，同文件中的其他任务留在原树。核对切片相对上游的完整差异，运行覆盖该行为的最小可执行检查。例如，迁移共享定义时，应查清包内和跨包的所有引用，并验证全部受影响的包。

## 2. 用户阅读切片工作树

交给用户阅读前，固定上游基线、原树中本片的来源版本和切片初始快照，覆盖本片新增、修改及删除的内容。每片提取完成后，交代工作树绝对路径、分支、相对基线的完整 diff，以及单独合入后的可验收结果和它在整体改造中的位置。用户在切片工作树中阅读和修改。需要阅读导航时，对这份切片 diff 使用 [diff-reading-order](../diff-reading-order/SKILL.md)。用户确认读完时，记录其确认的最终切片版本，作为回写和创建 PR 的依据。

## 3. 检查快照，回写原树并创建 PR

评审中有修改时，将切片工作树的当前内容与初始快照比对，覆盖本片新增、修改和删除的文件。逐块将采纳的修改回写原开发工作目录。对照提取时的来源版本与原树现状，跳过已有的等价修改，保留用户后续编辑。遇到无法兼容的重叠修改，保留两边版本并指出冲突块，待用户决定后继续。

创建 PR 前确认原开发树已包含采纳的修改，并验证最终切片与用户确认的快照一致。若验证引入新修改，请用户补读受影响的部分，再次核对和回写。按授权提交。推送前核对实际提交树相对固定基线的完整差异与用户确认版本一致，再按授权推送并创建 PR。操作结果不明时，按远端源仓库、分支、实际提交和目标分支核对本轮发布状态，只续做已证实未完成的动作。交接工作树路径、分支、提交 SHA、PR 链接、验证及回写结果。

## 4. PR 合入后 rebase 原开发树，缩小剩余 diff

可在一片合入后同步，也可将多片合入结果一次同步。fetch 并固定最新目标上游，逐个核实该基线已包含的切片 PR 及其实际合入提交。squash 或 rebase 合入时使用上游实际产生的提交，核对最终 diff、评审期间的修改及后续 revert。

1. 固定原分支 HEAD，保存可恢复的工作目录快照，覆盖文件内容、模式、删除及未跟踪文件。按仓库已有的恢复流程，将开发分支 rebase 到固定的最新上游。原分支没有独有提交时可快进。改动大面积重叠时，先在隔离副本验证恢复。
2. 确认目标上游已是开发分支祖先。对照快照和各 PR 的实际合入结果，逐块确认已合入的改动退出剩余 diff，未合入切片和其他本地改动（含同文件中的改动及未跟踪文件）仍完整。PR 最终实现与原树有差异时，保留仍需迁移的部分，将新写的冲突解法交给用户阅读。遇到并发编辑或无法确定取舍时，保留恢复快照，指出具体差异。逐片记录 PR、实际合入 SHA 和本次同步后的开发 HEAD。
3. 同步验证通过后，按 [cleanup-worktree](../cleanup-worktree/SKILL.md) 逐片处置已合入的切片工作树。只有该树在清理授权内、工作树干净且提交可从保留的远端引用恢复时才移除，并验证目录和 Git 工作树登记消失。否则保留该树，记录授权、待保存内容或恢复依据的缺口。清理范围限于该切片工作树，删除分支和恢复引用需要单独授权。逐片记录移除或保留的结果。
