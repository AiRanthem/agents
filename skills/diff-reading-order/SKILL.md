# Diff 阅读顺序

给出便于理解契约、实现和调用链的阅读顺序，说明顺序依据和可证明边界。保持只读。

## 确定范围

有指定范围时，按对应的分支、提交区间、PR、文件或代码块取证，并说明实际采用的基线和比较语义。三点比较从选定的共同祖先到目标，两端比较取端点内容差异。固定用于比较的提交 OID，同一文件按指定的暂存、工作区或提交版本识别代码块。未指定范围时，比较 HEAD 与工作目录的合并差异，用 `git --no-optional-locks status --porcelain --untracked-files=all` 识别相关未跟踪文件。读取本地 diff 时禁用自动刷新索引和有副作用的外部比较。没有 HEAD 时，以索引、工作区和未跟踪内容建立范围。注明排除项，工作区变化时复核受影响的范围和结论。

识别变更主线，检查重命名、删除、生成文件与源文件的关系。已删除文件结合基线内容和原调用方解释。以同一范围和版本统计、排序并检查覆盖。统计仅计入范围内已有的变更文件和增删行，包括纳入范围的未跟踪文件。已有差异之外，若有证据表明需要补改调用点或测试，按依赖给出这些位置及其原因，标明待补改。范围外的已审依赖只作阅读上下文。

## 建立有依据的顺序

约定 `A → B` 表示 A 依赖 B，阅读时 B 优先于 A。依据相关 import、符号使用、同包关系、测试编译依赖、schema 与生成关系建图；包级 import 不能证明对包内每个文件都有直接依赖。必要时经过未变更的中间节点追踪，作为上下文注明。

依赖优先的第 0 层是“不依赖其他待排序节点”的节点，后续层仅依赖已排定节点。环内节点合并为一组说明相互关系，再对组排序。测试在所依赖的生产代码之后；跨包测试须等待其全部相关依赖，不能只按文件名附在目标旁边。

区分规范与派生资料：已确认设计、接口契约可先读以建立意图；行为派生文档在对应实现之后核对。文档和入口文件的顺序取决于实际关系。契约、配置、运行时注册和动态调用可能形成 import 之外的关系；标注已确认的语义依赖和不确定项。

## 输出与完成

先说明范围内已有 diff 的文件数、可统计的增删行数，以及手写代码与生成文件、文档等派生内容的占比。注明占比口径，并单列二进制等无法计入的内容。简述范围和主线后，按依赖给出分组编号清单。为每个列出的文件（含组内文件）提供可点击的 Markdown 链接，附变更要点或补改原因，以及排序理由。以仓库相对路径作链接文字，目标使用当前界面支持的格式，定位到对应版本和行。已删除文件链接至可访问的基线或 PR 文件视图。无法链接到精确版本或文件时，说明限制并提供可核对的版本、路径及符号或行号。图仅在帮助理解时使用，并标注箭头含义。

输出前核对链接目标及行号与所述版本和位置相符，确认链接可访问。核对全部指定代码块和待补改位置已列出或明确分组，且跨组已知依赖先于消费方。说明依赖环、语义例外和缺失证据。

阅读导航完成即停止。用户边读边改后，只重新分析受变更影响的依赖和原结论，不承诺已读部分永久不受影响。
