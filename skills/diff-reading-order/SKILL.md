# Diff 阅读顺序

给出便于理解契约、实现和调用链的阅读顺序，说明顺序依据和可证明边界。保持只读。

## 确定范围

默认使用 `git diff HEAD` 覆盖暂存及未暂存变更，并用 `git status --porcelain` 识别相关未跟踪文件。展开属于任务范围的新增目录；列明排除的无关文件。支持用户指定的分支、commit 区间和 PR，说明实际采用的基线与比较语义：三点比较是共同祖先到目标，两端比较是端点内容差异。没有 HEAD 时使用索引、工作区和未跟踪内容建立范围。

识别变更主线。检查重命名、删除、生成文件与源文件关系；已删除文件结合基线内容和原调用方解释。大型生成文件可以成组列出，但保持范围可核对。

## 建立有依据的顺序

约定 `A → B` 表示 A 依赖 B，阅读时 B 优先于 A。依据相关 import、符号使用、同包关系、测试编译依赖、schema 与生成关系建图；包级 import 不能证明对包内每个文件都有直接依赖。必要时经过未变更的中间节点追踪，作为上下文注明。

依赖优先的第 0 层是“不依赖其他待排序节点”的节点，后续层仅依赖已排定节点。环内节点合并为一组说明相互关系，再对组排序。测试在所依赖的生产代码之后；跨包测试须等待其全部相关依赖，不能只按文件名附在目标旁边。

区分规范与派生资料：已确认设计、接口契约可先读以建立意图；行为派生文档在对应实现之后核对。文档和入口文件的顺序取决于实际关系。契约、配置、运行时注册和动态调用可能形成 import 之外的关系；标注已确认的语义依赖和不确定项。

## 输出与完成

简述范围和主线，输出分组编号清单，每项提供文件链接、变更要点和排序理由。图仅在帮助理解时使用，并标注箭头含义。核对全部范围内文件已列出或明确分组，确认跨组已知依赖均先于消费方；环、语义例外和缺失证据单独说明。

阅读导航完成即停止。用户边读边改后，只重新分析受变更影响的依赖和原结论，不承诺已读部分永久不受影响。
