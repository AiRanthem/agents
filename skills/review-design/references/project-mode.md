# Project design-review ownership

Authorized read-only reviews use the [read-only project route](../../manage-workitems/references/commands.md#reading-and-setup), retaining a separate temporary report. Opening a checkpoint, modifying its candidate and registering results follow the serial project workflow. Any local session may perform an authorized project operation; actual author/reviewer independence and input bindings determine review eligibility.

Read [shared project context](../../manage-workitems/references/project-context.md) and the [fixed command workflow](../../manage-workitems/references/commands.md). These write instructions apply to the controller or an ordinary expressly authorized project review session, including a fresh subagent assigned that entire ordinary review workflow. An autonomous stage executor returns actual artifacts to its controller, which operates the ordinary checkpoints.

Ordinary project review requires an explicit user request and an independent reviewer. In authorized `$advance-project`, the controller schedules the review under existing scoped authorization; no separate user session or renewed stage permission is required. Actual independence from authorship of the reviewed version remains mandatory. In autonomous advancement the controller only registers the real executor result through the applicable project workflow; it does not conduct a missing review, complete findings itself or substitute its own session for the reviewer identity. The ordinary independent review session performs its own assessment.

A retained genuine independent Pass may be carried forward only through the project operator/controller's `design-reuse` applicability checkpoint under the [command contract](../../manage-workitems/references/commands.md). That assessment is distinct from this skill's independent review; authorship does not prevent an authorized project operator from assessing unchanged applicability, but it cannot establish a missing independent Pass or approve material changes.

In autonomous mode, the [controller](../../advance-project/references/coordinator.md) opens the ordinary design-review checkpoint with the actual `--reviewer-session`, hands its complete inputs and candidate to the reviewer, and registers the actual report and verdict. The stage executor does not open another checkpoint.

Formal project design review uses the current published versioned spec. Formal publication records user approval and the version binding for this authorized review. Bound `derived_reuse_pending` evidence retains genuine original approval and Pass for comparison after applicability could not be established. This pending evidence permits only independent comparison of the candidate with the original approved contract; it permits neither implementation nor a skip waiver. Read the complete returned `design_basis.review`, `approval`, `read` and `read_hashes` for that comparison. An independent failure followed by an authorized contract-internal `design-update` repair preserves this basis and `derived_reuse_pending`; the failure still blocks reuse and the repaired candidate still needs actual independent pass with `--contract-unchanged`. Use a retained genuine Pass for the authorized owner/controller’s `design-reuse` applicability checkpoint when eligible; otherwise assess the published candidate independently. If no versioned spec exists, report that design input gap and preserve review authorization for continuation. Reuse does not resolve a pending user-owned contract decision or authorize a material contract change. For a directly requested ordinary project review, run `begin design-review ID` without a result, read the complete current requirement/spec and original instruction payload, and write only its returned candidate `spec.md` and `report.md` drafts, permitting candidate edits solely for mechanical corrections under the shared standard. For a corrected candidate, record the exact diff, evidence and unchanged contract, review its final exact identity, and finish pass with the declared `--mechanical-correction --contract-unchanged --provenance SOURCE`; no new author or reviewer is required. Undeclared candidate edits are rejected. Use current inputs and primary repository evidence. Earlier review reports may support retained coverage only after checking their exact identities, independence and applicability under the [coverage-reuse rules](implementable-gate.md#reuse-independent-coverage); obsolete conclusions cannot establish current Pass. After the actual review, execute the returned base `finish_command` with its declared `--result pass|fail --provenance SOURCE` arguments. When a pending candidate needs contract-preservation confirmation, add the declared `--contract-unchanged` only with pass and only when the actual independent reviewer confirms that the candidate has not changed the original approved contract; otherwise retain findings or return the user-owned contract decision. The program binds the actual reviewer, result and current inputs and derives design state. Follow the fixed status branch; do not manually edit YAML or repeat project Git/Aone checks. A scoped user waiver is not a review pass.

For a delegated report-only review, read the complete current contract, original project/main-workspace/source instructions and stable artifact identity supplied by the project operator. Assess independently, write only the assigned report and any expressly authorized mechanical candidate corrections, and return actual session identity, reviewed requirement/spec versions and hashes, source baseline, result, findings and report path. For a mechanical correction, also return the corrected candidate/hash, exact diff, determining evidence and explicit contract-preservation confirmation. The operator compares those inputs with the current target and registers `begin design-review ID --reviewer-session SESSION --review-file FILE`, then finishes with the actual result/provenance and reviewer-supplied correction flags. A checkpoint opened before assessment may receive its report in the designated draft. The reviewer differs from all substantive design authors/revisers and from the external-review registrar. Registration preserves the actual reviewed candidate and report bytes; never add unreviewed corrections or invent review provenance. These contribution assertions remain the registrar’s responsibility.

Use the report workflow to record review state; keep the spec focused on its design contract, and claim `implementable` only when the program records the matching independent pass on the approved contract. Read-only planning stays read-only; report the assessment without a project checkpoint.

Under [stage executor](../../advance-project/references/stage-executor.md), the reviewer reads the original contract and evidence, writes only its assigned report and permitted mechanical corrections in the designated candidate, and returns actual identity, input identity, findings and artifact identity. It never runs project `begin`, `finish`, Git/Aone publication or official-document writes. A separate `$explore-design` author/revision worker returns substantive candidate corrections; mechanically corrected candidates can retain the same independent reviewer and same-round verdict. Return their actual pass with `candidate_file`, `mechanical_correction: true` and `contract_unchanged: true`; the controller persists the exact candidate and evidence without changing the original substantive authors. The controller publishes the candidate and preferentially reuses the original still-independent reviewer for affected assessment.
