# Project design-review ownership

Read [shared project context](../../manage-workitems/references/project-context.md) and the [fixed command workflow](../../manage-workitems/references/commands.md). These write instructions apply to the controller or an ordinary expressly authorized project review session, including a fresh subagent assigned that entire ordinary review workflow. An autonomous stage executor uses its controller's bound receipt flow instead.

Ordinary project review requires an explicit user request and an independent reviewer. In authorized `$advance-project`, the controller schedules the review under existing scoped authorization; no separate user session or renewed stage permission is required. Actual independence from authorship of the reviewed version remains mandatory. In autonomous advancement the controller only registers the real executor result through the applicable project workflow; it does not conduct a missing review, complete findings itself or substitute its own session for the reviewer identity. The ordinary independent review session performs its own assessment.

In autonomous mode, use the [coordinator receipt workflow](../../advance-project/references/coordinator.md); `autonomy dispatch/result` owns the underlying checkpoint. Do not start a second ordinary review checkpoint.

For an unowned ordinary project item, run `begin design-review ID` without a result, read the complete current requirement/spec and original instruction payload, and write only the returned report draft. Use current inputs and primary repository evidence; do not load obsolete review files as assessment evidence. After the actual review, execute the returned base `finish_command` with only its declared `--result pass|fail --provenance SOURCE` arguments. The program binds the actual reviewer, result and current inputs and derives design state. Follow the fixed status branch; do not manually edit YAML or repeat project Git/Aone checks. A scoped user waiver is not a review pass.

For an ordinary item owned by an active developer, the owner may assign a report-only independent review. Read the complete current contract, original project/main-workspace/source instructions and stable artifact identity supplied by the owner. Assess independently, write only the assigned temporary report, and return actual session identity, reviewed requirement/spec version and hashes, source baseline, result, findings and report path. Run no project commands and claim no official status update. The owner compares those inputs with the current target before `begin design-review ID --reviewer-session SESSION --review-file FILE` and the ordinary result/provenance finish. Both external fields are required together; the reviewer differs from the design author, approval session and registrar. The program retains the source owner, checks the source report hash through publication and preserves the report in the project. Identity and reviewed-target assertions remain the trusted owner's responsibility; this route does not authenticate host identities or authorize takeover.

The spec has no machine-status frontmatter. Use the report workflow instead of generic status-field writes, and claim `implementable` only when the program records the matching independent pass on the approved contract. Native Plan stays read-only; report the assessment without a project checkpoint.

Under [stage executor](../../advance-project/references/stage-executor.md), the reviewer reads original contract and evidence, writes only assigned report/candidate paths, and returns actual identity, input identity, findings and artifact identity. It never runs project `begin`, `finish`, Git/Aone publication or official-document writes. If it corrects a candidate through `$explore-design`, it cannot pass that version; the controller publishes the appropriate candidate and arranges a fresh independent reviewer.
