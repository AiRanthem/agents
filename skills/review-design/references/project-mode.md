# Project design-review ownership

Authorized read-only reviews use the [read-only project route](../../manage-workitems/references/commands.md#reading-and-setup) without takeover, retaining a separate temporary report. Opening a checkpoint, modifying its shared candidate or registering results uses the current write claim; an owner may delegate bounded candidate corrections under its claim.

Read [shared project context](../../manage-workitems/references/project-context.md) and the [fixed command workflow](../../manage-workitems/references/commands.md). These write instructions apply to the controller or an ordinary expressly authorized project review session, including a fresh subagent assigned that entire ordinary review workflow. An autonomous stage executor returns actual artifacts to its controller, which operates the ordinary checkpoints.

Ordinary project review requires an explicit user request and an independent reviewer. In authorized `$advance-project`, the controller schedules the review under existing scoped authorization; no separate user session or renewed stage permission is required. Actual independence from authorship of the reviewed version remains mandatory. In autonomous advancement the controller only registers the real executor result through the applicable project workflow; it does not conduct a missing review, complete findings itself or substitute its own session for the reviewer identity. The ordinary independent review session performs its own assessment.

A retained genuine independent Pass may be carried forward only through the owner/controller's `design-reuse` applicability checkpoint under the [command contract](../../manage-workitems/references/commands.md). That assessment is distinct from this skill's independent review; authorship does not prevent an authorized owner from assessing unchanged applicability, but it cannot establish a missing independent Pass or approve material changes.

In autonomous mode, the [controller](../../advance-project/references/coordinator.md) opens the ordinary design-review checkpoint with the actual `--reviewer-session`, hands its complete inputs and candidate to the reviewer, and registers the actual report and verdict. The stage executor does not open another checkpoint.

Formal project design review uses the current published versioned spec. Formal publication attests user approval obtained before writing; separate `decision-record` approval registration is not a review prerequisite. Bound `derived_reuse_pending` evidence retains genuine original approval and Pass for comparison after applicability could not be established. This pending evidence permits only independent comparison of the candidate with the original approved contract; it permits neither implementation nor a skip waiver. Read the complete returned `design_basis.review`, `approval`, `read` and `read_hashes` for that comparison. An independent failure followed by an authorized contract-internal `design-update` repair preserves this basis and `derived_reuse_pending`; the failure still blocks reuse and the repaired candidate still needs actual independent pass with `--contract-unchanged`. Use a retained genuine Pass for the authorized owner/controller’s `design-reuse` applicability checkpoint when eligible; otherwise assess the published candidate independently. If no versioned spec exists, report that design input gap and preserve review authorization for continuation. Reuse does not resolve a pending user-owned contract decision or authorize a material contract change. For an unowned ordinary project item, run `begin design-review ID` without a result, read the complete current requirement/spec and original instruction payload, and write only its returned candidate `spec.md` and `report.md` drafts, permitting candidate edits solely for mechanical corrections under the shared standard. For a corrected candidate, record the exact diff, evidence and unchanged contract, review its final exact identity, and finish pass with the declared `--mechanical-correction --contract-unchanged --provenance SOURCE`; no new author or reviewer is required. Undeclared candidate edits are rejected. Use current inputs and primary repository evidence. Earlier review reports may support retained coverage only after checking their exact identities, independence and applicability under the [coverage-reuse rules](implementable-gate.md#reuse-independent-coverage); obsolete conclusions cannot establish current Pass. After the actual review, execute the returned base `finish_command` with its declared `--result pass|fail --provenance SOURCE` arguments. When a pending candidate needs contract-preservation confirmation, add the declared `--contract-unchanged` only with pass and only when the actual independent reviewer confirms that the candidate has not changed the original approved contract; otherwise retain findings or return the user-owned contract decision. The program binds the actual reviewer, result and current inputs and derives design state. Follow the fixed status branch; do not manually edit YAML or repeat project Git/Aone checks. A scoped user waiver is not a review pass.

For an ordinary item owned by an active developer, the owner may assign a report-only independent review. Read the complete current contract, original project/main-workspace/source instructions and stable artifact identity supplied by the owner. Assess independently, write only the assigned temporary report and any expressly authorized candidate mechanical corrections, and return actual session identity, reviewed requirement/spec version and hashes, source baseline, result, findings and report path. For an authorized mechanical correction, also return the corrected candidate path/hash, exact diff, determining evidence and explicit confirmation that the contract is unchanged. Run no project commands and claim no official status update. The owner compares those inputs with the current target before `begin design-review ID --reviewer-session SESSION --review-file FILE` and the ordinary result/provenance finish, carrying `--contract-unchanged` only from the actual independent reviewer’s explicit confirmation when required. If the report includes an authorized mechanical correction, copy only the actual reviewed final candidate into the returned `spec.md` draft and supply the mechanical/contract-preservation flags with that reviewer’s pass; never add independent corrections during registration. A completed external report uses both fields; a checkpoint opened before assessment may supply the actual reviewer session first and receive its report in the designated draft; the reviewer differs from all recorded substantive design authors/revisers and the registrar of an external review. Recording a real user approval alone is not design authorship. The program retains the source owner, checks the source report hash through publication and preserves the report in the project. Identity and reviewed-target assertions remain the trusted owner's responsibility; this route does not authenticate host identities or authorize takeover.

The spec has no machine-status frontmatter. Use the report workflow instead of generic status-field writes, and claim `implementable` only when the program records the matching independent pass on the approved contract. Read-only planning stays read-only; report the assessment without a project checkpoint.

Under [stage executor](../../advance-project/references/stage-executor.md), the reviewer reads the original contract and evidence, writes only its assigned report and permitted mechanical corrections in the designated candidate, and returns actual identity, input identity, findings and artifact identity. It never runs project `begin`, `finish`, Git/Aone publication or official-document writes. A separate `$explore-design` author/revision worker returns substantive candidate corrections; mechanically corrected candidates can retain the same independent reviewer and same-round verdict. Return their actual pass with `candidate_file`, `mechanical_correction: true` and `contract_unchanged: true`; the controller persists the exact candidate and evidence without changing the original substantive authors. The controller publishes the candidate and preferentially reuses the original still-independent reviewer for affected assessment.
