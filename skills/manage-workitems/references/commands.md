# Direct project file maintenance

The agent reads and edits the project's actual Markdown, YAML and configuration files in place using ordinary file and Git tools. [Schema](schema.md) gives the layout; [workflow](workflow.md) describes the business facts to record.

## Reading and setup

Locate the selected management root from its instructions and existing project configuration. Read the affected requirement, design, context and metadata, plus original instructions for associated business/source workspaces. Resolve item names against the actual inventory; ask only if the intended target remains ambiguous.

A status report reads existing facts. A requested project-record change includes the corresponding in-place edits and their project-branch commit and push. Preserve a read-only task's boundary.

## Operations

Create an item with an unused ID and supplied requirement/context. Update titles, dependencies, archive markers and document routes directly in metadata. Write design, review, implementation, acceptance and delivery records from actual work. Maintain complete current documents and use Git history for superseded versions.

Keep hierarchy, dependency and fix links consistent. Inspect a prerequisite's actual state when relevant and record concrete missing facts in context. A command result alone grants no business approval or proof of completed work.

## Publication

After writing, commit the affected project files and push the configured branch. Exclude unrelated changes and separate source repositories. If Git rejects the push, preserve the commit and resolve the actual issue within the authorized scope. Optional external synchronization has its own result under [Aone](aone.md).

During autonomous advancement, the controller reads the selected scope, delegates authorized stages and writes their actual results to the same records. Executors retain their real authorship and review attribution.
