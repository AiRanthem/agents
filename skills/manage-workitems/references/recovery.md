# Restore and recover a project

Cloning the exact configured project branch restores published current requirements, design, current pointer-bound evidence and project state. Git history provides prior versions. It does not restore machine-local bindings, tools, credentials, unpublished code or the separate main workspace. Start the agent at the project root and read its generated `AGENTS.md`. Install missing shared skills through their installation contract.

Use `project.py status` for the fixed reported facts. For an interrupted operation, run only its returned resume command and then follow the [status table](commands.md#fixed-write-workflow). Preserve local identity and recovery files. Report unresolved ownership, publication or backend facts without choosing another journal action, manually editing YAML, repeating an uncertain create or assuming a timeout releases ownership.

Autonomous advancement resumes from `autonomy status` for its exact authorized scope. Preserve coordinator identity, current attempt and captured receipts; a running item or unknown old owner requires confirmed liveness/ownership before recovery. Never synthesize a result or infer completion from elapsed time. Preserve actual observable call IDs only; do not fabricate one or search private logs to fill it. A missing call ID uses explicit local receipt-hash provenance. Mixed-scope `autonomy authorize` returns skipped items in `blocked_items`; continue other authorized ready items without taking over the skipped scope. A contract change requires a current user decision, and changed review inputs require fresh independent evidence.

The program reports confirmed failures before any push separately from unresolved publication outcomes. These rejected attempts do not block `status`; their local intent remains available. A retained candidate with an uncertain push remains subject to publication recovery checks.

Schema-1 projects permit diagnostic reads and explicit `migrate`. `upgrade-project` runs that deterministic migration/instruction refresh; active ownership and unresolved sync block it with concrete facts. Source hashes make repeat execution a no-op. The agent writes complete current business instructions from the explicit current source when the program reports that input is needed. Existing user-maintained authority remains valid; migration does not routinely request reapproval. If the source leaves a real business change or permission unknown, report that specific gap. Migration does not retain obsolete prompts as active project content; earlier versions remain in Git history.

The program returns required original main-workspace instruction paths. Read them before dependent work. If a binding, original instruction or code location is missing, report the listed missing input; do not infer a new path or repair layout yourself. Changing a binding does not move dirty worktrees or transfer a claim. Follow [the command contract](commands.md): `status: blocked` with `code: stale_ticket` returns the sole allowed restart command, while `code: stale_evidence` is blocked without a continuation command until current authorization/review evidence is supplied.

Project removal uses [delete-project](../../delete-project/SKILL.md) with an exact authorized local manifest. It preserves remote branches and Aone history by default, along with main-workspace roots, shared environments, sibling projects and unrelated worktrees. Unpublished content and uncertain external outcomes require preservation or resolution before removal; removal is not a recovery shortcut.

For an interrupted autonomous dispatch, follow the [autonomous continuation contract](commands.md#autonomous-advancement) and keep its actual worker paused. Resolve any returned lower-level `next_command`, then execute `continuation_command` (`autonomy resume ID --attempt ATTEMPT`) to continue the same coordinator, worker and attempt. It reuses the retained workflow ticket and input/read guards. A settled publication is insufficient: release the worker only after the complete `ready` context with `worker_paused: false`. Never redispatch or replace a worker to bypass an uncertain preparation.

When stale inputs invalidate a completed worker's result, use `autonomy retire` only with the original actual worker's terminal receipt and confirmed descendant cleanup. This closes the unusable attempt without accepting its old verdict; a subsequent explicit user startup is required before another stage. Unknown liveness remains blocked.

A partial result checkpoint also returns `continuation_command`. Continue that same attempt through `autonomy resume`: the program first recovers its exact retained journal, then reuses the signed local receipt/artifact capture and result ticket. If interruption prevented linking the journal, recovery requires a unique owned pending publication whose saved writes match the capture hashes; an unrelated publication remains blocked and unchanged. A lower-level recovery command remains available for diagnosis, but its confirmed `publication_rejected_before_push` does not discard the outer captured result: the attempt continuation revalidates all current guards before a fresh publication of those same immutable bytes. Unknown push outcomes or journal/ownership/guard conflicts remain blocked on the original evidence; keep the worker paused and report that blocker. If finalization already applied, that continuation is an exact no-op; lower-level publication success alone is not the outer-stage completion signal.

Predevelopment snapshot/prepare operations resume the same recorded intent with the same command after settling any returned publication continuation. Retain snapshot commit/ref and generation identity; verify exact remote readback, never overwrite a moved snapshot or create a new identity for an uncertain publication. The original speculative worktree remains retained during isolated convergence. See [predevelopment](../../advance-project/references/predevelopment.md).
