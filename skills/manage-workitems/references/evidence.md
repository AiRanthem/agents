# Current project evidence

Write findings, verification and handoff directly into current context or the appropriate report. State scope, original source, observed result and uncertainty. Separate observations, interpretations, executed checks and unperformed checks.

Review reports identify the actual reviewer, assessed design/source version, findings and conclusion. Acceptance identifies the user's actual statement and accepted work. Delivery identifies the achieved obligation and supporting remote, release or runtime evidence. Registrar identity does not replace those sources.

Keep decisions and operational knowledge as coherent current documents. Replace superseded prose rather than accumulating event transcripts. Retain useful original reports with clear applicability; use Git history for earlier versions.

Reusable knowledge belongs in `evidence/<id>.md`; optional same-ID YAML can describe `id`, `topic`, `summary`, `repository`, `scope`, `kind`, `sources` and relevant inputs. Read source material when applying a finding to changed work. Saved results describe their observed scope, not a new live verification.

Commit and push completed project-record changes under [persistence](persistence.md). Never put credentials or secret values into project evidence.
