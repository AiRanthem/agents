# Evidence and independent review

Evidence distinguishes observed facts, inferences, search coverage and verification limits. Read primary requirement/spec and raw source pointers from the operation's complete `read` payload. A cached summary or previous review cannot establish the current contract, an absence claim, ownership or delivery.

For actual repository investigation within the user's requested scope, retain source paths/symbols, revisions or relevant content identity, configuration and observed outcomes. A matching HEAD does not identify dirty tracked/untracked source or dependency inputs. Claims such as “all callers” require a bounded search universe; new files or configuration may invalidate that coverage.

Current item facts, verification and handoff go through `context-update`. Reviews and delivery use the returned report drafts for their operation; the program writes paired Markdown/YAML records with requirement/spec/base/session and code snapshot bindings. Retain only the current records referenced by review, delivery, waiver, cleanup or snapshot state, plus pending recovery artifacts. Decisions use `decision-record` to replace the complete current decision document; use the actual user input and provenance when recording an approval, but do not accumulate superseded decision text. The program treats Markdown as opaque text and does not detect semantically obsolete passages. Do not create ad hoc project evidence paths or edit a YAML record to assert that a gate passed.

The shared knowledge store is separate from item records and does not require an item pointer. Use `knowledge-show ID` through the command contract to get the body path, hashes and exact guarded update/remove commands. Replace the entire Markdown body when updating; metadata YAML is maintained by the program. Use `knowledge-remove` only when the entry is explicitly obsolete or no longer useful. No-pointer status alone is not grounds for removal, and the program does not parse body semantics or identify stale claims. Do not hand-edit metadata YAML or replace a body with a partial append.

Independent reviewers form their own assessment from original inputs before reading previous findings. A different session is necessary but does not itself prove a review happened. Record the real review source and result; never manufacture provenance to satisfy a command. Design review additionally requires the user's explicit invocation, separately or as part of scoped autonomous advancement. The implementation workflow may require its final fresh-subagent review within the authorized item.

Autonomous evidence includes trusted-coordinator-captured real spawn/result receipts with raw native host data, bound to the item, role, attempt, worker and current contract/dirty code inputs. Raw data must contain the matching native worker identity; a real arguments/result capture can retain identity such as `arguments.target` when the result omits it. `call_id` is optional and must be actually observable; never fabricate one or inspect private logs to fill it. Without one, `coordinator-capture-sha256:<receipt hash>` identifies the local capture, not a host call. No host signature is provided; these structural checks prevent stale or mismatched reuse but cannot authenticate a dishonest coordinator or prove semantic review quality. Preserve the original user approval and complete captured requirement/spec/decision in `approved_contract` for `derived_revision`; its new independent reviewer compares that original approved contract with the candidate before returning `contract_unchanged: true`. A derived revision must not be represented as new user approval. An `autonomy accept` source must be actual user acceptance of the bound current artifact and code tree; command success establishes structural acceptance recording, while the user/reviewer assesses substantive criteria.

Verification claims name their practical limit: unit test, build, CI, merge, release, deployment and end-to-end evidence are distinct. Evidence applies only to the code, inputs and acceptance it actually covers. A delivered prerequisite, fix or rebase may invalidate a baseline even when spec bytes match. The program rechecks structural bindings; agents and reviewers remain responsible for deciding whether evidence substantively covers acceptance criteria and for reporting only what they verified.
