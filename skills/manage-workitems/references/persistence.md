# Project publication

Write project documents, metadata and configuration directly at their final paths. Commit the completed task's affected project files and push the configured branch normally. The current local checkout is the working state. Preserve unrelated edits and existing source work.

Use the repository's established remote and branch mapping. Include related document/metadata changes in a coherent commit. Project-record publication does not include separate source repositories or authorize code submission, deployment, messaging or deletion.

A failed commit or push leaves files and any created commit available for correction. Report the actual error and resolve the Git issue from current content within the task's authorization. Do not discard user work or force-push to clear a failure.

Update an optional external backend through available service tools under its configured scope. Report Git publication and external synchronization separately. Preserve actual external IDs and unresolved outcomes so a later attempt does not duplicate work.
