Creation ends at metadata and requirement skeletons. Design and independent design review require the user's requested scope. Implementation requires current approval/review or an explicit user-scoped design-review waiver, actual prerequisite delivery and published ownership. A waiver never manufactures a review pass and is rechecked against current contract/base/dependencies. A post-delivery defect gets a separate linked fix item; retain the original item's verified delivery evidence. Keep code submission, actual delivery and local cleanup as separate authorized outcomes.

The design owner obtains user confirmation before publishing the complete formal spec, reusing covering approval of an unchanged contract. Publication attests approval; separate approval registration is not required before an authorized independent review. An oversized item includes its whole design, usable stages and DAG and selects `design-update --next-action split` before review. Current independent Pass routes to decomposition, with inherited child specs ready for their own review. Only demonstrated blocking gaps require supplementary child design; future refinement never reduces parent design rigor. For execution handoff, source replacement and internal resources, use the typed lifecycle contract, preserving frozen baseline gates, exact source recovery and separately adopted collection policy.
