# Ordinary managed-project implementation

For script blockers or defects, [user-authorized manual recovery](../../manage-workitems/references/recovery.md#user-authorized-manual-recovery) defines the approved state/file correction and script repair path. Preserve actual evidence, permissions and source recovery.

Use only for ordinary managed-project development, not an autonomous stage executor. Read [project context](../../manage-workitems/references/project-context.md) and the fixed [command workflow](../../manage-workitems/references/commands.md). The program owns YAML, document routes, baseline/review/dependency/fix gates, worktree preparation and Git/Aone publication.

During human acceptance, apply [the final-draft contract](../../complete-workitem/references/delivery-and-cleanup.md#human-final-drafts) to user-requested code and design edits in the retained worktree. Record the real user finalization source and preserve the final drafts without another review or automatic correction. These edits remain in human acceptance; use `development-start` for an explicitly requested return to ordinary agent development. The implementation/review gates below govern that ordinary development.

In execution mode, start requested implementation through `begin development-start ID` and execute its returned finish command before code edits. Read-only planning reads the project context and returns its implementation plan without state mutations. Read the complete payload and required original instructions. A current independent design review normally gates implementation. Only the user's explicit scoped `--skip-design-review --approval-source SOURCE` may bind the unchanged requirement/spec/base/dependencies instead; do not invent a review pass or `implementable` status.

Use returned Markdown drafts for project document updates, including approved contract corrections. Resume recorded development, preserve read-only planning read-only behavior and leave source submission to user instructions.

For the final project review, resolve the review mode with `review-implementation` before delegating: honor the user's existing choice or ask once whether to use multi-agent review. Invoke the skill in a fresh independent subagent with that resolved mode, then pass its actual result, provenance, reviewer session and report file through `begin development-finish ID` and execute the returned finish command unchanged. Follow the command contract's returned statuses. A future review promise does not satisfy the gate; unavailable host capability is an explicit incomplete boundary.
