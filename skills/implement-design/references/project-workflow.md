# Ordinary project implementation

Use this reference for ordinary project development. An autonomous executor follows its assigned [stage scope](../../advance-project/references/stage-executor.md). Read [project context](../../manage-workitems/references/project-context.md), the complete approved contract, actual review findings, prerequisite behavior and original project/main-workspace/source instructions.

Use the actual recorded code worktree or create the authorized source location under repository conventions. Preserve unrelated work and useful prior implementation. Record repository, branch, base, source path and current progress directly in the project's existing files. Resolve consequential contract gaps or unavailable dependencies before affected implementation while continuing independent authorized work.

Maintain authorized project document and metadata changes in place and commit and push coherent updates under [persistence](../../manage-workitems/references/persistence.md). Source commits, pushes and PRs require covering user instructions. Read-only planning performs no file or state writes.

During human acceptance, apply [the final-draft contract](../../complete-workitem/references/delivery-and-cleanup.md#human-final-drafts): preserve user-finalized code and design and record the real conclusion, aligning only text left for reconciliation. Report acceptance separately from tests and independent review.

For an authorized final project review, resolve the `review-implementation` mode, honoring the user's choice. Give a fresh independent reviewer the complete stable target and actual verification evidence. Record its real result, findings, identity and report directly in the project. Unavailable review capability is an incomplete result; a future promise is not review evidence.
