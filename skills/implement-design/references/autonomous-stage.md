# Autonomous implementation or correction

The controller assigns one work item and one implementation or correction attempt with approved inputs, source worktree, permitted output paths and result identity. Loading this skill for a fix retains that fix attempt. Verify those inputs and the current dirty state before editing. Missing or stale inputs go back to the controller; do not acquire ownership or manufacture approval evidence yourself.

Implement and verify the approved contract using this skill's quality core, then return the actual result, primary evidence and unresolved decisions. Keep source uncommitted except a dispatched `baseline` or `rebase` stage: load [predevelopment](../../advance-project/references/predevelopment.md) and commit only in its assigned isolated generation for that bound Git transformation. Do not call project CLI, update formal project documents or metadata, register review evidence, or publish project Git/Aone changes. Write only designated source or candidate/report artifacts. Supply approved contract corrections as candidate content for controller registration rather than overwriting formal designs.

The controller schedules independent code review and any later fix attempt. Do not expand this implementation or fix stage into a work-item manager or run the next stage yourself. Self-review and required verification remain your responsibility; a report of implementation success is not independent approval or human acceptance.

Organize descendants, choose their model and effort where the host supports it, integrate their evidence and close their resources under the shared stage-executor contract. Ordinary main-agent routing or automatic escalation rules do not constrain that organization. Actual host safety, permissions and capacity still apply.
