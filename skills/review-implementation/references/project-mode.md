# Project implementation review

Authorized read-only reviews use the [read-only project route](../../manage-workitems/references/commands.md#reading-and-setup) and retain a separate temporary report. The controller records actual results directly in project files; reviewed source remains read-only.

Prepare the shared original context and review plan without findings, then follow the [mode contract](review-standard.md#resolve-review-mode) before assessment or reviewer dispatch. The calling workflow owns mode selection: the project operator/controller passes the already-resolved choice to the fresh reviewer; direct invocation asks once only when undecided. A delegated review lead returns a missing mode to the caller rather than selecting a default or asking the user again.

Read the current complete requirement and spec, applicable original instructions, comparison baseline and the actual stable source snapshot supplied by the controller. Do not seek historical review conclusions before your own assessment. Include staged, unstaged and relevant untracked contents; HEAD alone is insufficient.

The stage executor edits only its designated report, keeps source read-only and returns findings, outcome, resolved mode, actual identity, input binding, snapshot, commands and provenance. It does not write formal project state. The controller records the real assessment and target under [direct file maintenance](../../manage-workitems/references/commands.md). It does not substitute its own judgment for the independent review. Missing essential coverage or execution cannot become a review pass. In `single-agent`, the one qualified reviewer independent of implementation and fixes covers correctness, quality, security, tests and high-risk boundaries in place. In `multi-agent` review, the independent lead dispatches multiple facet reviewers from the prepared context, then personally assesses critical behavior, test oracles and omissions, validates their results and synthesizes the report. Planned essential assignments and high-risk targeted coverage must actually run under the review standard.

In ordinary project development or autonomous advancement, the controller supplies the resolved review mode and real target to the independent reviewer. It then records the actual result, report, reviewer identity and provenance directly in the existing project records and commits and pushes that metadata. Native tasks remain with the coordinating agent. Source submission, delivery and cleanup retain their separate authorization boundaries.
