# Project implementation review

Resolve mode first under the [shared contract](review-standard.md#resolve-review-mode-first). Autonomous `advance-project` uses `single-agent` without a mode question on every host. An ordinary owner/controller passes the already-resolved choice to the fresh reviewer; direct invocation asks once only when undecided. The reviewer returns a missing mode to the caller rather than asking again.

Read the current complete requirement and spec, applicable original instructions, comparison baseline and the actual stable source snapshot supplied by the controller. Do not seek historical review conclusions before your own assessment. Include staged, unstaged and relevant untracked contents; HEAD alone is insufficient.

The stage executor edits only its designated report, keeps source read-only and returns findings, outcome, resolved mode, actual identity, input binding, snapshot, commands and provenance. It never calls project commands or records its own review. The controller uses the [command workflow](../../manage-workitems/references/commands.md) or [autonomous coordinator](../../advance-project/references/coordinator.md) to bind real evidence to current inputs. It does not substitute its own code assessment. A runtime rejection or missing mode-specific coverage or execution cannot become a review pass. In `single-agent`, the one qualified reviewer independent of implementation and fixes covers correctness, quality, security, tests and high-risk boundaries; no quality child or additional review perspective is required. In `multi-agent`, the quality child and high-risk independent targeted perspectives must actually run under the review standard.

In ordinary project development, the authorized owner/controller may invoke this skill in a fresh subagent with the resolved mode and pass its real result, provenance, reviewer session and report file to `begin development-finish ID`, then execute the returned finish command. In autonomous mode the controller uses the same ordinary checkpoint with the actual reviewer identity; it may open the checkpoint before review and receive the actual report in its designated draft. Native workers are managed by that agent outside project state. Source submission, delivery and cleanup remain separate authorization boundaries.
