# Project implementation review

Authorized read-only reviews use the [read-only project route](../../manage-workitems/references/commands.md#reading-and-setup) and retain a separate temporary report. Opening a checkpoint and registering results follow the serial project workflow; reviewed source remains read-only.

Prepare the shared original context and review plan without findings, then follow the [mode contract](review-standard.md#resolve-review-mode) before assessment or reviewer dispatch. The calling workflow owns mode selection: the project operator/controller passes the already-resolved choice to the fresh reviewer; direct invocation asks once only when undecided. A delegated review lead returns a missing mode to the caller rather than selecting a default or asking the user again.

Read the current complete requirement and spec, applicable original instructions, comparison baseline and the actual stable source snapshot supplied by the controller. Do not seek historical review conclusions before your own assessment. Include staged, unstaged and relevant untracked contents; HEAD alone is insufficient.

The stage executor edits only its designated report, keeps source read-only and returns findings, outcome, resolved mode, actual identity, input binding, snapshot, commands and provenance. It never calls project commands or records its own review. The controller uses the [command workflow](../../manage-workitems/references/commands.md) or [autonomous coordinator](../../advance-project/references/coordinator.md) to bind real evidence to current inputs. It does not substitute its own code assessment. A runtime rejection or missing mode-specific coverage or execution cannot become a review pass. In `single-agent`, the one qualified reviewer independent of implementation and fixes covers correctness, quality, security, tests and high-risk boundaries in place. In `multi-agent` review, the independent lead dispatches multiple facet reviewers from the prepared context, then personally assesses critical behavior, test oracles and omissions, validates their results and synthesizes the report. Planned essential assignments and high-risk targeted coverage must actually run under the review standard.

In ordinary project development, the authorized project operator/controller may invoke this skill in a fresh subagent with the resolved mode and pass its real result, provenance, reviewer session and report file to `begin development-finish ID`, then execute the returned finish command. In autonomous mode the controller uses the same ordinary checkpoint with the actual reviewer identity; it may open the checkpoint before review and receive the actual report in its designated draft. Native workers are managed by that agent outside project state. Source submission, delivery and cleanup remain separate authorization boundaries.
