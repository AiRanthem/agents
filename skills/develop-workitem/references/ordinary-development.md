# Ordinary project development

Read [project context](../../manage-workitems/references/project-context.md), current requirements, design, decisions and the original project/main-workspace/source instructions. Use the actual recorded source location. Maintain project documents and metadata directly at their final paths and commit and push coherent project updates under [persistence](../../manage-workitems/references/persistence.md).

For requested design, use `explore-design` to maintain the complete current spec and effective decisions. Reuse approval of the unchanged contract; present material choices for the user's decision. Record genuine approval and design-review evidence with their actual authors and targets. For an oversized item, first complete the full design, delivery stages and dependency graph, then use `split-workitem` after independent review. Children inherit the relevant contract and need further design only for actual gaps.

For an authorized design review, use `review-design` and its [project mode](../../review-design/references/project-mode.md). Supply stable original inputs to an independent reviewer; record its actual result and report without adding unreviewed changes. Preserve valid prior coverage under the [coverage-reuse rules](../../review-design/references/implementable-gate.md#reuse-independent-coverage); assess changed assumptions and interactions before relying on it.

For requested implementation, read the approved contract, actual review findings and prerequisite behavior. Reuse the existing worktree or create the authorized source location using the repository's conventions. Record its repository, branch, base and path. Use `implement-design`; resolve substantive missing requirements or unavailable dependencies before affected code work, and continue independent authorized work.

For the authorized final independent implementation review, resolve the review mode using `review-implementation`, honoring the user's existing choice. Supply the complete stable code target to a fresh independent reviewer and record its actual findings, result, identity and report. Keep context current with verification results, remaining uncertainty and source location. Passing review leaves real human acceptance and delivery pending.

During human acceptance, apply [the final-draft contract](../../complete-workitem/references/delivery-and-cleanup.md#human-final-drafts). Preserve user-finalized code and design, record the actual user conclusion, and align only outdated text left for reconciliation. Source submission and cleanup remain separately authorized. For a replacement implementation or execution-mode change, preserve existing code and recovery references under [resource preservation](../../manage-workitems/references/resource-lifecycle.md).
