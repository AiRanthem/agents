# Develop Work Item

Use this skill for the phase the user requested. A recorded requirement does not authorize source investigation, design or code preparation. Keep sessions rooted at the management project; use an explicit workdir and that repository's original instructions for source operations.

Use installed `manage-workitems/scripts/project.py` through the [fixed command contract](../manage-workitems/references/commands.md). Run the requested `begin OP ID` with its required typed inputs, read its complete payload and required original main-workspace instructions, edit only returned Markdown paths, then execute its returned `finish_command`; only design review supplies result/provenance arguments to that finish command after assessment. `development-finish` requires the actual reviewer result, provenance, reviewer session and report file as `begin` inputs. `published` or `no_op` ends that checkpoint; `partial` permits only its returned resume command; for `status: blocked` with `code: stale_ticket`, execute only the returned `next_command`, while `status: blocked` with `code: stale_evidence` has no continuation command and requires current authorization/review evidence. Otherwise report the listed blockers or missing facts. The program owns YAML, document selection, owner/session identity, worktree resolution, gates and Git/Aone checks.

For requested design, use `design-update` and `explore-design` to maintain the complete current spec. Preserve explicit upstream assumptions and unresolved decisions; stable design may precede prerequisite delivery. Reconcile relevant assumptions with delivered code before formal review. Use `decision-record` to replace the complete current decision document, retaining effective decisions without a transcript of superseded decisions; `--approval-source SOURCE` records existing explicit approval of the current design. The program derives raw-byte design versions and `draft`/`review-pending` state. Keep machine state out of spec frontmatter.

Independent design review starts only on the user's explicit request in a separate session. `begin design-review ID` returns the original inputs and review draft before a result is chosen. After the actual assessment, execute its returned base finish command with only the declared `--result pass|fail --provenance SOURCE` arguments. A current independently passing requirement/spec/base/session binding establishes `implementable`. Exploration and self-review cannot manufacture that result.

For requested implementation, use `development-start ID` with its required typed code inputs. The program reuses or prepares the recorded development and publishes ownership before code edits, checking prerequisites, upstream fixes and current contract/review bindings. For a simple requirement, only the user's explicit waiver for this unchanged contract permits `--skip-design-review --approval-source SOURCE`; it records a scoped waiver without inventing a review pass or `implementable` design. Do not infer a waiver from a broad implementation request or migration. A changed contract, dependency or baseline needs the program's current gate and any newly required user fact.

After a successful start, invoke `implement-design` for the approved contract. Its final fresh-subagent `review-implementation` is authorized by this project workflow. Pass the actual reviewer result, provenance, reviewer session and report file to `begin development-finish ID`; then run the returned finish command unchanged. Use `context-update` for current facts, verification, snapshot identity, remaining findings and handoff. A passing implementation review awaits actual delivery; tests or local commits do not establish delivery.

Preserve existing ownership and development across machines; a new session or elapsed owner age does not authorize takeover. An unfinished fix blocks affected downstream checkpoints, including active sessions. Code stays uncommitted for the user's final inspection unless the user explicitly requests code commits/pushes. Use [complete-workitem](../complete-workitem/SKILL.md) only for the separately requested actual delivery or cleanup phase.
