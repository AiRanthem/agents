# Project work

Read current requirements, design, decisions, context and metadata. Perform the user's requested work and update those files directly with actual results. Commit affected project records and push the configured branch. Use installed `manage-workitems` for the layout and substantive skills for design, implementation, review and delivery.

Follow each item’s recorded delivery obligations. Current items require the source change to be merged; record that outcome only from actual merge evidence.

Creation ends at supplied requirements and known obligations. Designs contain the complete current contract and actual user decisions. Reports retain real author/reviewer identity, assessed scope and findings. Keep prerequisites and unresolved questions visible.

Human acceptance records the user's actual conclusion. Preserve final code/design and update descriptive text within the requested scope. Reviews, tests, source pushes, merges, releases and runtime outcomes are distinct evidence. Record delivery and cleanup only for what occurred.

Decomposition preserves the complete parent design and gives children cohesive contracts and explicit relationships. Source replacement and cleanup preserve useful work and exact recovery locations and cover only authorized resources.
