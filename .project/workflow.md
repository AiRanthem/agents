# 项目工作流

阅读[项目配置](project.yaml)、[业务指令](business-instructions.md)及相关工作项的需求、设计、决定、上下文和元数据，按用户请求和已有授权直接更新原文件。通过 `manage-workitems` 维护稳定 ID 和工作项关系，设计、评审、实现、验收、交付和清理使用对应的共享技能。

创建项目时登记已知需求和验收、交付要求。设计保存完整的当前约定、用户决定、前置依赖和待决问题。评审与实现记录实际范围及版本，保留作者、评审者、发现和验证结果。

同一验收目标使用一个工作项，可以通过多个 PR 交付。经用户授权后，可用 `manage-workitems` 把已获批准且通过独立评审的设计拆成需要单独排期、分工或验收的子项。父项保留完整设计和整体验收，子项记录各自的验收范围和依赖，父子记录一起发布。交付后的缺陷通过 `fixes` 关联原工作项。

人工验收记录用户实际接受的代码和设计。测试、独立评审、源码推送、合并、发布、部署和端到端验证按实际结果分别记录。按授权替换或清理源码工作树时，保全有用的本地成果并记录可核验的恢复位置。

检查修改后的路径、引用和事实。核对本次推送将新增的全部提交均在授权范围内，再提交相关文件并普通推送到[项目配置](project.yaml)指定的分支。保留无关本地改动。推送失败时保留本地成果并报告原因。外部系统同步记录实际结果和待确认事项。
