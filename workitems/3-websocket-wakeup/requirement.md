# 基于 WebSocket 事件的 Sandbox 自动唤醒

## 目标

已有 Sandbox 处于 Pause 时，通过 WebSocket 接入的合法 IM 消息事件能够自动恢复目标 Sandbox，使其中的应用重新具备消息处理能力。

能力面向通用 IM 平台与应用，用户要求以统一解决方案应对所有 IM；飞书长连接订阅与 Sandbox 内 OpenClaw 是首个场景。需要覆盖应用内旧连接已失效的休眠状态，不能仅以 Pause 后短时间内连接尚存作为成功依据。具体平台接入条件、适配与验收范围由设计明确，既有 15 平台调查不代表全部平台已经适配。

首期交付统一接收/唤醒/交付框架及飞书适配，以飞书验证完整链路；其他平台后续按共同接口扩展，不将全部 15 个已调研平台纳入首期实现与验收。

## 已确定范围

- 覆盖已经存在、处于 Pause 的 Sandbox。自动唤醒开启时，允许合法业务消息恢复手动 Pause 或自动休眠的目标；关闭自动唤醒时，不因新消息恢复已暂停的目标。
- 休眠期间，必须有一个仍在运行、位于暂停边界外的组件承担消息感知责任，并把消息关联到目标 Sandbox；该责任不能依赖沙箱内旧连接继续存活。
- 采用外部接收组件、各 IM 适配器与统一唤醒核心的方向，允许调整应用接入方式，由应用通过内部接口接收事件。上游长连接由外部组件持续维护。
- 将合法业务事件关联到正确目标，在授权边界内触发恢复，并定义应用就绪后的事件处理行为。
- 每个平台账号/接入绑定一个已有 Sandbox；同一账号的用户和群聊消息均交给该目标，不按用户或群聊分流到不同 Sandbox。一个 Sandbox 可以绑定多个 IM 账号/接入。
- 由运维在 Sandbox 外维护平台账号、接收凭据引用、固定目标 Sandbox 与应用事件入口。绑定和凭据保存在沙箱外的可恢复配置中，与允许进程退出丢失的内存消息队列分开；应用采用外部接收模式，不承担自行注册或持续续租责任。
- 发送者和群聊的消息投递范围依赖 IM 平台自身的权限控制。外部接收组件不额外配置发送者/群聊唤醒白名单，也不复制应用的业务访问规则；唤醒前仍须校验平台来源、账号绑定和目标 Sandbox 的唤醒授权。
- 平台连接及事件协议由适配层承担，通用能力不能限定为飞书或 OpenClaw 专用逻辑。
- 与 `2-feishu-wake-openclaw` 为同级独立需求，可分别交付和验收。

首期支持飞书普通消息事件 `im.message.receive_v1`，同步卡片回调等其他事件后续另行扩展。启用外部接收模式时，应用不再建立同账号的接收长连接，使用匹配的应用适配版本。

## 机制约束

Sandbox 内被暂停的客户端不能执行 handler、心跳或重连；TCP 缓冲、连接状态与业务 ACK 不能代替可靠接收。平台有限重试不构成无限离线保留承诺。

必须区分业务事件与心跳等控制消息，普通心跳及重连活动不应作为业务唤醒信号。飞书同一应用的多个客户端会竞争接收事件，不能依赖额外连接旁路监听全部消息。

通过平台来源、账号绑定和目标唤醒授权校验的业务消息可以触发恢复。应用收到后继续执行其原有业务访问策略，可能忽略或拒绝已经触发唤醒的消息；外部接收层不据此增加发送者或群聊过滤。

消息在外部接收组件的内存中暂存，并按平台协议及时确认，再唤醒和交付。用户接受接收进程退出时，已确认但尚未交付的内存消息可能丢失。恢复后首次交付临时失败，最多再重试 5 次；仍失败则记日志放弃。平台接收确认、Sandbox 恢复、应用接收和业务执行完成分别观察。应用内部入口在原生队列接纳后返回 HTTP `202` 和相同交付 ID；不等待 Agent 完成。容量、期限、恢复失败和重试边界以已批准的 [正式设计](spec.md) 为准。

首期同账号单活、受控重启；旧实例未确认停止时不自动接管。配置和凭据在外部可恢复，变更通过受控重启生效。任务固定目标的不可复用实例身份，恢复和最终交付不能因同名重建转向新实例。内存条数、字节数、消息存活期限、唤醒等待和单次交付超时均须显式有限配置；超限不接纳、不成功确认，任务超时后记录原因并放弃。

停用账号接入时，停止接纳该绑定的新业务消息并关闭接收连接；已接收消息沿原目标继续原有的有限唤醒和交付，不增加清空队列或专门取消流程。停用后旧消息仍可能恢复原 Sandbox，但仍须通过原目标身份和有效唤醒授权校验；已发起的恢复和应用已接收的工作不回滚，接收进程退出仍适用既定的内存消息丢失边界。换绑采用先结束旧绑定、再新建绑定的方式，旧消息不迁移到新目标。

## 验收要求

基础场景：承载 OpenClaw 的 Sandbox 已 Pause，应用内旧连接全部失效，外部接收服务和绑定有效。用户发送允许处理的飞书普通消息后，平台及时得到确认，原实例恢复，应用原生队列接纳事件，OpenClaw 正常处理并回复。

- 手动 Pause、自动唤醒关闭、控制消息、来源／目标授权失败分别符合既定边界。
- 不同消息分别保留与交付；回执丢失时重试保持交付和原生事件身份，沿用应用原有有限去重能力。
- 同名重建不会使旧消息操作新实例，内存超限不会产生成功平台确认。
- 恢复超时、应用临时失败和接收器退出分别遵循有限处理或消息丢失约定。
- 停用不接纳新消息，原任务按原目标有限处理，换绑不迁移旧任务。

完整可观察结果及公共能力、应用适配、集成三部分的交付依赖见 [正式设计](spec.md)。配置数值表达处理上限，不承诺固定冷启动或最终回复时延。

## 关系与交付

本项从原 `2-feishu-wake-openclaw` 的双接入范围中拆出，与收敛后的 Webhook 唤醒需求并列；`split_from` 记录来源，不表示父子层级或前置依赖。

目标映射、授权、恢复合并、就绪检测及适用的交付机制可共享，共同实现归属在设计中确定。若通过内部 HTTP 接口交付应用，该接口不自动形成对“公网 Webhook 入口唤醒”功能的依赖。
