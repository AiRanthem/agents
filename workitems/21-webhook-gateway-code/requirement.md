# Webhook 唤醒与优雅下线代码

## 目标与范围

作为父项 `2-feishu-wake-openclaw` 的代码子任务，在 agents 的 Gateway 中承接合法飞书 IM Webhook 事件，使已有 Pause Sandbox 恢复并向其中的应用交付事件。用户最新明确这是单独的飞书 IM Webhook 功能，采用标准飞书事件订阅协议，OpenClaw 为目标应用场景。本项包含 Webhook 接收、身份与目标校验、唤醒和应用交付，以及这些内存任务的正常下线排空；不要求先实现通用多 IM 框架。

## 已确认契约

- 首期每个接入绑定一个已有 Sandbox；用户、群聊及 Agent 会话路由由应用负责。自动唤醒开关开启时，手动 Pause 和自动 Pause 均可被合法消息唤醒。
- 合法事件登记到进程内任务所有者后再 ACK，异步唤醒并交付。用户允许进程退出导致未完成事件丢失，不要求数据库、持久队列或跨进程恢复。
- 未授权事件不得触发恢复；URL challenge 与普通消息事件需要区分。飞书协议处理复用既有 Gateway 路由和唤醒机制。
- 普通事件按标准 HTTP 200 确认接收：Gateway 登记内存后向飞书确认，目标应用的标准 Webhook 接口返回 HTTP 200 后结束成功交付等待；不要求 OpenClaw 私有 durable 标记，也不代表模型或回复已完成。转交保留原始 body 和相关签名头。目标应用必须符合该协议接收语义，challenge 不计为普通消息交付。
- 沿用当前有效的唤醒等待配置；等待失败或超时记日志并结束该事件。唤醒后立即首次投递，连接失败、超时/响应丢失或非 HTTP 200 时指数退避，最多再重试五次（共最多六次请求）；成功即结束，耗尽后记日志放弃并释放任务，不启动下一轮或写持久失败队列。
- 实际 ACK Chart 当前默认唤醒等待为 600 秒，覆盖二进制的 60 秒缺省；具体安装覆盖值未读取，依有效配置运行。该常态等待与下线 60 秒排空分别计时，依据见 [配置与有限投递](../../evidence/feishu-webhook-config-and-retry.md)。
- 每次 HTTP 请求与退避采用有限时限；从内存登记起，总预算不超过唤醒等待、六次 HTTP 超时及五次退避之和，排队/重试不刷新截止。下线 60 秒绝对截止先到则提前终止。保留原事件 ID，响应丢失导致的重复投递由应用去重，不承诺恰好一次；日志不含凭据或完整正文。有限默认参数与总预算推导由实现者落实，仍须兼容目标验签时间窗。
- 内存任务覆盖排队与执行中的事件；ACK、客户端断连、Envoy stream 销毁不会取消已接收任务，也不能继续使用已销毁 stream 的 API。停收与事件接收登记必须互斥。
- 提供仅限 Pod 内调用的本地管理入口。首次 drain 原子停收，新 Webhook 返回 503，不入队、不 ACK、不唤醒；readiness 返回失败，liveness 正常。保留内部路由就绪状态、路由同步、peer 与 outbound 等任务依赖。
- **从首次停收开始最多等待 60 秒**，全部任务结束即提前返回。等待到应用有效确认接收，不等待 OpenClaw 模型执行或飞书最终回复。到期停止重试、取消剩余任务并记录未完成情况，继续退出；成功、失败终态与排空超时必须区分。
- drain 幂等，重复调用沿用首次绝对截止时间，不重新开放接收或延长预算；调用方断连不撤销 draining，不取消已接收任务。管理入口不得经业务 listener 暴露。
- 业务排空在 preStop 阶段完成，然后才进行 Envoy 连接 drain 和 TERM 后清理；不把排空放进既有 8 秒 StopProcess 清理中。具体 ACK 编排由子任务 22 接入。

## 验收方向

- 合法事件在 Sandbox Pause 时被内存接收、确认、唤醒并交给应用；非法事件不会触发唤醒。
- 与 drain 并发的事件要么完整登记并纳入等待，要么收到拒绝；不存在已 ACK 却未登记的事件。
- 已接收事件在 HTTP stream 结束后仍可完成；下线期间保留依赖直至业务排空结束。
- 空任务集立即返回；有任务时最多等待 60 秒；重复 drain 不延长窗口；超时继续退出且明确记录未完成结果。
- 收到应用接收确认就结束该事件的成功交付等待，模型回答不阻塞 Gateway 下线。

标准飞书事件接收协议已确定；完整 E2B 数据面 URL 可复用 Host 解析定位 Sandbox 和端口。现有 token/JWT 门禁不识别飞书来源凭据，域名也不包含对象 UID；飞书专用入口需接入相应验证，并使异步任务遵守既有对象身份约束。内存上限、满载与上游重复事件合并、验证配置及开关变化规则仍需与父项一起收敛；失败有限重试和放弃按用户最新决定执行。依据见 [入口核验](../../evidence/feishu-e2b-webhook-entry.md)。本轮修订尚未独立复核，以上不是完整正式 spec 或独立审查通过记录。

父项保存整体需求与集成验收责任，子任务 22 承担实际编排与后续集成验证记录。本项不修改 ack-components。
