# 修复 SandboxSet 有限等待引入的单测耗时回归

## 问题与目标

工作项 [2-sandboxset-create-consistency](../2-sandboxset-create-consistency/requirement.md) 通过 [PR #1207](https://github.com/openkruise/agents/pull/1207) 为 SandboxSet 查询增加每次最多 5 秒的纯 informer 等待。生产行为符合已批准合同，但既有单测反复触发真实等待，导致串行执行的全仓库单测明显变慢。

用户要求“解决这个问题，恢复单测的效率”，在 PR 已合并后明确要求另开工作项、另提 PR 修复。本项作为已交付工作项 2 的独立缺陷，通过 `fixes` 关联。

## 已确认范围与约束

- 消除与测试目标无关的真实 5 秒等待，恢复 cache、E2B、sandboxcr、Manager 等受影响单测的执行效率。
- 保持已批准的生产合同：每次缓存查询最多等待 5 秒，只读 informer，保留独立 context、取消/提前截止、读取错误、namespace/selector 和既有上层返回语义。
- 保留等待、取消、读取失败、并发独立性和 APIReader 零调用等必要行为验证，不通过弱化断言、跳过必要用例或修改覆盖率门槛隐藏问题。
- 代码简洁优先，复用适合的既有测试机制，避免仅为追逐 100% 数字扩张实现。
- 不扩展 Ref 一致性能力、生产 API、部署或日志/指标体系。
- 不继续修改已合并的原 PR；修复在新分支、隔离 worktree 和独立上游 PR 中交付。

## 可观察验收与验证边界

1. 受影响的普通业务测试不再反复消耗真实 5 秒窗口，同时保留原有业务与隔离断言。
2. 专门覆盖缓存有限等待的测试仍能验证完整合同，时间边界、取消和独立调用行为不能因提速而失去验证。
3. 使用相同测试命令，在相近环境对修改前后受影响包进行计时，并与已记录的合入前 master/PR 结果对照，显示已确认的固定等待增量被消除；CI 总耗时受编译和 runner 波动影响，不承诺精确恢复到某个秒数。
4. 运行最小必要回归和涉及并发/取消的 race 检查，回读覆盖率结果；不将全部 CI 完成或硬性 100% 当作用户额外要求。
5. 将修复源码推送并创建针对 `openkruise/agents:master` 的独立 PR，项目记录保存真实验证与交付结果。
