# Webhook 唤醒 ACK 编排接入

## 目标与前置条件

将子任务 `21-webhook-gateway-code` 已交付的 Webhook 与正常下线能力接入实际 ack-components 编排，使滚动更新等正常 Pod 终止先停止接收并排空业务，再退出连接和进程。

**本项编排变更依赖子任务 21 的真实代码交付。** 可以提前细化契约和预算，不能以设计批准、独立审查通过或源码 push 代替代码合并交付。启用新 preStop 前，还需取得包含本地管理接口的可用 Gateway 镜像及其源码关联证据；旧镜像不能配新 hook。

## 已确认范围与约束

- 修改实际 ack-components 的组件包，具体目标版本与分支在开始编排实施前按主工作区规则确定。保持主检出在主分支，在隔离 worktree 完成修改；允许改动路径受原始 AGENTS.md 白名单约束。
- preStop 顺序为：调用 Gateway 本地业务 drain 并等待结果 → 调用 Envoy graceful drain → 等待连接 drain 时长 → hook 返回并由 Kubernetes 发送 TERM。
- Gateway 业务排空最多 60 秒，空任务集提前结束；本地管理调用上限按 65 秒预算，避免调用方先于服务端排空期限放弃等待。沿用 Envoy admin 调用最多 5 秒和默认连接 drain 30 秒。
- 总终止宽限期目标为 **120 秒**，对应 65 + 5 + 30 + 20 秒；最后 20 秒留给 TERM 后退出和调度开销。自定义配置需保持相同预算约束。已有编排核验值 90 秒是历史现状，不能直接用于新 60 秒业务排空方案。
- 排空开始后 readiness 返回失败，liveness 保持正常；本地管理入口不向业务网络暴露。管理调用失败或超时需要记录，仍继续连接退出流程，不误报业务排空成功。
- 使用已交付代码确定的接口及返回语义，镜像映射、Chart values 与 configs/default.yaml 保持一致。镜像或 hook 变化不能使目标包出现接口不匹配的中间交付状态。

## 验收方向

- 使用组件实际配置渲染后，Gateway 镜像包含新接口，preStop 调用顺序、调用超时与 120 秒总宽限期一致。
- 正常终止时先停收，已接收事件最多等待 60 秒，随后才执行连接 drain；提前排空无需睡满业务等待时长。
- 管理接口失败与排空超时可区分；新消息不被旧 Pod 确认接收，任务在业务排空阶段保留依赖。
- 记录接入后的真实 Webhook/Pause/Resume/交付及 Pod 正常终止集成验证结果；未授权或未执行的环境验证明确保留为未验证，不能用 Helm 渲染替代。

## 交付边界

本项仓库为 ack-components，保留源码合并交付义务；源码 push、MR 合并、镜像可用、组件发布和线上 rollout 是不同事实。具体目标分支、组件版本、环境与发布方式未确定，本次拆分不授权修改实际编排、发布或部署。

本项承担编排接入及其集成验证记录，父项汇总整体验收。源代码与接口实现由子任务 21 负责；本项的依赖不意味着工作项 1 或 WebSocket 工作项 3 已交付。
