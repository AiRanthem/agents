# 当前决策

- 用户要求同时支持 Webhook 和 WebSocket 两种 IM 唤醒方式。
- 用户要求将能力做成通用能力，飞书和 OpenClaw 作为具体场景。
- 2026-11-03，用户要求保存原理分析后，拆成 Webhook 唤醒与 WebSocket 唤醒两个并列需求。本项保留原 ID 并收敛为 Webhook 唤醒，同级新项 `3-websocket-wakeup` 承接 WebSocket 唤醒。
- 2026-11-03，用户要求“开始设计webhook唤醒的需求”，授权本项设计探索。
- 2026-11-03，在了解 OpenClaw 通过飞书消息 API 独立发送最终回复后，用户明确回复“那可以做可靠接收”。据此选定 Sandbox 外持久化成功后确认、再异步恢复与重试交付的方向。
- 可靠接收选择不确定具体存储产品、消息保留和重试期限、应用交付协议、故障容忍范围或最终业务回复保证；这些仍需细化。
- 此前提出的“每个接入绑定一个 Sandbox”及“开关开启时手动 Pause 也可唤醒”均为建议，尚未收到用户选择。当前没有完整正式设计批准、独立审查、实施或代码交付结果。
