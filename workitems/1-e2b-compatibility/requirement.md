# E2B 兼容性

## 目标

管理 OKA 的 E2B 兼容性问题，并在决定解决每个问题之前，与用户讨论其解决必要性。

## 范围

每个 E2B 兼容性问题均遵循以下顺序：记录问题与现有证据；与用户讨论是否需要解决；记录用户结论；经用户明确确认需要解决后，再进入该问题的设计。

这一要求适用于本总项及其后续子项。尚未确认的问题保持待讨论；确认暂不解决或无需解决的问题保留讨论结论。

2026-10-20，用户明确要求「解决上游 #1083 #1084 #1085 三个 Issue」，本轮范围限定为下列 OpenKruise Agents 问题。该指令提出了具体解决请求，不代表任何修复方案已获批准，亦不替代尚未完成的必要性与兼容范围讨论。

### #1083：Sandbox 列表筛选与排序

来源：https://github.com/openkruise/agents/issues/1083

上游报告：`GET /v2/sandboxes` 将官方 `order`、`template`、`startedAfter` 查询参数误当作 metadata，导致合法请求返回空列表；默认升序也与 E2B 默认降序不符。

上游期望：按模板 ID 或别名筛选；按 RFC3339 时间筛选在该时刻及之后启动的 Sandbox；支持 `asc`/`desc` 且默认 `desc`；分页游标与排序一致；保留参数不进入 metadata，不支持的参数值返回 400。

### #1084：Pause 忽略 memory

来源：https://github.com/openkruise/agents/issues/1084

上游报告：`POST /sandboxes/{sandboxID}/pause` 未读取请求体 `memory`，调用者要求仅保存文件系统时仍可能保存内存，并收到成功响应。

上游允许的解决边界：实现单次 `memory: false` 的 filesystem-only 暂停，或在暂不支持时明确返回 400 并说明限制；`memory: true` 或省略继续保持现有行为。完整支持与显式拒绝之间的取舍尚未确认。

### #1085：Snapshot 请求、过滤与响应不兼容

来源：https://github.com/openkruise/agents/issues/1085

上游报告：创建快照时 `name`、`memory` 未生效；`GET /snapshots` 忽略 `name` 筛选；创建和列表响应的 `names` 为 `null` 而非数组。

上游允许的解决边界：支持 filesystem-only 快照，或对暂不支持的 `memory: false` 明确返回 400；支持命名快照及名称筛选，或明确拒绝/说明限制；`names` 始终为数组，至少为 `[]`。命名能力及单次内存模式的实现范围尚未确认，不把简单保存名称等同于 E2B 同名快照新 tag 语义。

### 证据与待确认边界

三个 Issue 在 2026-10-20 查询时均为 OPEN，且无评论。报告复现基线为 OpenKruise Agents `ee289a6b0410f64eb03a59ee20b18f8cc59ed3cd`，对照 E2B OpenAPI `b52cd30c14bf7038ba5bfbd15456b1dabe567082` 和 SDK e2b 2.56.0；是否仍存在以当前开源代码核对结果为准。

下一步讨论三项影响及解决必要性，并确认完整能力支持与显式拒绝不支持参数之间的范围。尚无已批准设计、独立设计评审或源码实现；不扩大到其他 E2B 差异。

## 验收条件

对每个进入设计的具体兼容性问题，均能追溯到此前与用户的必要性讨论及用户明确确认需要解决的结论。

三项具体行为验收以上游期望为讨论输入；完整支持与显式拒绝的选择确认后，形成相应验收条件，不将静默忽略继续作为兼容行为。验证需覆盖合法请求、参数错误及相关既有行为回归。
