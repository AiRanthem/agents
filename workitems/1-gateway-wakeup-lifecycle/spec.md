# Gateway 流量自动续期

## 摘要

为通过 Gateway 使用的 Sandbox 增加按实际流量触发的自动续期。用户在 create metadata 中显式开启；Gateway 在新请求或双向数据到达时检查剩余生命周期，小于创建时 timeout 的 10% 才尝试续期。续期将剩余生命周期恢复为创建时的时长，不缩短已经接受的更晚有效截止时间。连接空闲不续期。

E2B connect 与 Gateway 共用生命周期核心能力，保持期限计算、暂停保留策略和受保护写入的一致性。Gateway 负责流量准入、触发条件和合并请求，不调用 E2B connect HTTP 接口。运行中续期异步执行；已暂停 Sandbox 的自动唤醒仍取决于已有唤醒配置。

本文是需求 1 的完整设计候选，等待用户确认完整契约；尚未建立独立评审结论。

## 背景

现有 Gateway 能在流量到达时唤醒允许自动恢复的 Sandbox，并为自动暂停场景重新设置暂停期限。它尚不在 Running 状态下根据持续流量延长期限，因此用户正在访问或接收流式输出时仍可能触发时间到期。

现有 connect 已包含运行中延长期限、暂停后恢复、恢复时长保护和暂停保留时间计算。直接调用底层 Resume 不会为已经 Running 的 Sandbox 续期；另写一套期限规则则会增加行为分歧和维护负担。复用 connect 的核心能力能够让两种入口采用同一套生命周期语义。

目标是让显式选择此功能的用户减少主动发送 connect 保活的需要。功能只响应经过 Gateway 的实际流量，不承诺单凭连接存续或后台计算持续运行就一直保活，也不取代既有暂停、删除和其他生命周期规则。

## 设计终态

### 开启方式与持久化

create 的 `metadata` 增加扩展键 `e2b.agents.kruise.io/auto-renew`：字符串 `"true"` 开启，缺省或 `"false"` 关闭；其他字符串及不符合 metadata 字符串类型的输入返回 400。现有原生路径、自定义路径及 v1/v2 create 入口行为一致。此键作为功能扩展参数消费，不新增响应字段或承诺将它作为普通用户 metadata 原样回显。

开启时，服务端保存经过默认值填充和既有校验的创建 timeout，记为 T。持久化到系统 annotation `agents.kruise.io/traffic-renewal-timeout-seconds`，值为正整数秒；该有效记录同时表示已经开启。它由 create 过程生成，外部 metadata 不能直接写入该系统键。Gateway 不从创建时间与当前截止时间反推 T，也不相信普通透传 metadata 里的自报时长。

从模板 Claim 或从 checkpoint Clone 创建的新 Sandbox 都只采用本次 create 的选择：未开启时清除继承的续期记录；开启时写入本次 T。T 随这一次 Sandbox 交付保存，Gateway 重启后仍可读取。后续显式 connect、setTimeout、暂停与恢复只改变当前期限，不改写 T。

never-timeout 保持没有生命周期期限；同时传入开启选项不为它增加期限或续期记录。已有 Sandbox 缺少有效记录时不自动开启；存储值缺失、非法或不可安全表示时跳过续期并对非法值记录诊断，不猜测或回填 T。本次不增加运行时启停 API、CRD spec 字段、模板级默认开关或阈值配置项。

### 流量与触发条件

只有按现有 Gateway 规则获得准入并定位到具体 Sandbox 的请求才产生续期资格。其新请求到达、非空请求数据及非空响应数据均可触发检查，包括正常 HTTP、SSE 和 WebSocket。沿用已有流级鉴权语义，不逐数据块重新认证；续期始终绑定该流最初获得准入的 Sandbox 身份。

流量按非空字节事件计算，不解析业务内容。因此 SSE 心跳、WebSocket 心跳也属于流量；空回调、连接仍打开、连接关闭事件以及 Gateway 自己生成的拒绝响应不算流量。经过其他入口或直接访问 Pod 的流量不在范围内，Sandbox 主动访问外部的流量也不在范围内。

有效截止时间 E 沿用 connect 的选择：存在 `pauseTime` 时使用它，否则使用 `shutdownTime`。Running 且尚未要求暂停、未进入删除的同一 Sandbox，满足 `0 < E - 当前时间 < T × 10%` 时可发起续期。恰好等于阈值不续期；已经到期时不通过普通续期抢救，后续按既有生命周期执行。首次流量检查与重试都要尊重当前状态和当前记录。

阈值首版固定为 10%。没有流量时不进行周期性保活。事件检查使用本地缓存；不为每个数据块发管理请求或 Kubernetes 请求，不保留或记录数据内容。

### 共用 connect 核心能力

共用范围是协议无关的生命周期计算和执行能力：有效期限选择、按时长计算期限、自动暂停与销毁模式、暂停保留时间、恢复最短时长、只延长规则，以及保持身份和并发条件的持久化。将需要共享的能力放在 Gateway 可依赖的中立边界，现有 connect 通过其 Manager/Infra 路径调用；共享代码不依赖 E2B handler、HTTP 模型或状态码，不扩大 Gateway 对 API/Manager 包的遗留依赖。

API 层继续负责 API Key、所属用户、请求校验和 E2B 响应。Gateway 继续负责其现有流量准入、初始 T 和阈值判断、异步任务及本地请求合并。Sandbox Controller 继续负责观察期限并执行暂停/删除，不引入对 API 或 Manager 的反向依赖。

调用核心能力时区分显式 connect、流量续期和获准的流量唤醒：显式 connect 保持原有行为；流量续期只允许更新 Running Sandbox 的期限，不允许恢复暂停状态；流量唤醒只有通过现有自动唤醒条件才允许恢复。复用不改变既有 connect API、setTimeout 的主动改期语义或响应结构。

### 运行中续期

一次续期首次计算目标时固定基准时间 t，目标有效截止时间为规范化后的 `t + T`，沿用现有整秒时间精度。重试同一次工作不不断推进 t，不把目标计算为旧截止时间再加 T。

对于自动销毁模式，只延长 `shutdownTime`，不产生 `pauseTime`。对于自动暂停模式，延长 `pauseTime`，并按 connect 的同一暂停保留策略计算配套 `shutdownTime`。暂停保留时长独立于 T；缺失或非法的保留策略沿用 connect 的默认和诊断规则，仅在实际接受的期限更新中写入必要的默认值。

“只延长”约束的是有效生命周期截止时间，不能把暂停后的保留窗口误当作 Running 生命周期。若其他请求已经把有效期限延长到目标之后，本次不缩短它。普通续期不使用恢复过程的最短 5 分钟规则，始终使用原始 T。

显式 setTimeout 仍可缩短当前期限，且不改变 T。开启此功能后，后续合格流量可能再次把期限延长为 T；需要及时停止 Sandbox 时，应使用既有暂停或删除操作，而不能依靠缩短 timeout 禁止后续续期。

### 与自动唤醒的关系

续期与自动唤醒是独立选择。仅开启续期不会使 Paused Sandbox 自动恢复，也不会绕过 Gateway 的唤醒总开关。Running Sandbox 的续期不依赖唤醒总开关。

两者都开启且通过既有唤醒条件时，共用 connect 核心能力以保存的 T 发起恢复。计时 Sandbox 沿用现有恢复保护，将本次恢复时长取为 `max(T, 300 秒)`；这不改写保存的 T。解除暂停与初始新期限必须在同一次受保护状态更新中完成，避免旧期限在恢复途中生效。恢复成功后按 connect 的既有完成阶段延长期限，并保持只延长规则；流量等到 Sandbox Ready、路由可用后再转发。

自动暂停模式重新设置暂停期限和对应的暂停保留窗口；自动销毁模式只重新设置销毁期限。无期限对象仍保持无期限。未开启续期的 Sandbox 继续使用已有唤醒行为。恢复失败、等待超时或请求取消继续沿用现有唤醒的返回和取消语义。

### 并发、身份与失败

所有流量触发的期限写入及唤醒状态变更，都在执行前和每次条件写重试中核对当前对象的 namespace/name、UID 和公开 Sandbox ID，确保仍为最初获得准入的交付，不操作同名替代对象。普通续期还要重新核对有效续期记录、Running 状态、暂停意图、删除状态和阈值；身份变化、对象消失、策略移除、已要求暂停或删除时终止此次续期，绝不写 `paused=false`。获准的唤醒则重新核对唤醒资格和删除状态，保持既有并发恢复的幂等语义。

后端写入采用版本条件，只修改本次需要更新的期限和必要策略字段。Gateway informer 中被裁剪的模板等字段不得因更新而被擦除。发生冲突后重读并重新判断，不使用旧模式、旧身份或旧阈值判断强行覆盖新状态；本次新增流量续期使用缓存和条件写实现，不新增 APIReader 直读依赖。

同一 Gateway 对同一 Sandbox UID 合并并发触发，工作量和等待队列有界。多个 Gateway 可以竞争，但以存储中的最新对象和条件写决定结果；一个已完成的续期会使其他请求不再满足阈值。不会因 N 个并发流量事件而累计增加 N 个 T，也不引入跨 Gateway 分布式锁。

运行中续期异步执行，不阻塞数据转发。失败时记录可定位的结构化错误，不改变正在服务的响应或断开流；后续流量可以在退避后再次触发。一次工作及其冲突重试必须有截止时间；无新流量时不形成无限后台重试。网络返回不确定时不把本地期限标成已成功，后续根据实际观察重新判断；同一次工作重试仍使用固定目标，避免重复延长。

流结束后不再产生新触发；已经接收的有界续期可完成，成功写入不因客户端断开而回滚。后台工作不持有已销毁流的 Envoy 回调或数据缓冲；Gateway 停止时取消尚未完成的工作。日志不得包含访问凭证或业务数据，本次不新增 Prometheus 指标。

### 兼容性与能力边界

没有续期记录的对象保持原行为，不迁移历史对象。新 API 与支持该能力的 Gateway 配合才能提供完整能力：旧 API 不生成系统续期记录，旧 Gateway 忽略它；混合版本期间不能保证任意一条流量路径都触发续期。升级、回滚均不将无期限对象转为计时对象。

本功能延长生命周期期限，不改变访问令牌有效期、代理空闲超时、负载均衡连接限制或其他主动暂停规则。它不能阻止手动暂停/删除、探针驱动暂停、集群故障或已经发生的到期动作。接近到期时的突发流量和后端故障可能来不及续期；异步设计提供尽力续期，不承诺每一次合格流量都能阻止到期。

### 可观察验收结果

| 场景 | 结果 |
| --- | --- |
| T 为 600 秒，剩余 60 秒时有新请求 | 不更新期限 |
| T 为 600 秒，剩余 59 秒时有新请求或流内数据 | 异步尝试将有效期限延长至本次计算时间加 600 秒 |
| 只有下行 SSE 数据或 WebSocket 心跳持续经过 Gateway | 与新请求采用相同阈值和续期规则 |
| 连接一直打开但没有数据，或命令一直计算但不输出 | 不因连接存在而续期 |
| 同时有大量流量命中多个 Gateway | 续期不累加为多个 T，已接受的更晚有效期限不被缩短 |
| T 为 30 秒，Sandbox 已暂停且允许流量唤醒 | 恢复时至少设置 300 秒；保存的 T 仍为 30 秒，后续 Running 续期继续使用 30 秒 |
| 续期任务排队期间对象已要求暂停，或同名对象 UID 已替换 | 该任务不恢复暂停、不写新对象 |
| 写入发生冲突、超时或结果不确定 | 业务流保持现有转发行为，不虚报续期成功，不无限重试 |
| 自动暂停与自动销毁两种模式 | 分别保持原模式，暂停保留时长不被原始 timeout 替换 |
| 没有开启记录、历史对象或 never-timeout | 不产生新的自动续期行为 |
