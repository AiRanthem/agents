# Gateway 流量自动续期

## 摘要

为通过 Gateway 使用的 Sandbox 增加按实际流量触发的自动续期。用户配置续期阈值 H 和目标时长 R；Gateway 在新请求或双向数据到达时检查剩余生命周期，未到期且小于 H 才尝试延长到续期时刻起 R。没有阈值即关闭，连接空闲不续期。

create 通过 metadata 配置，connect 和 timeout 通过扩展 header 按字段修改。阈值接受 duration 或相对于本次请求 timeout 的百分比，目标仅接受至少 2 秒的整秒 duration；持久化时均为绝对 duration。create 的目标缺省为创建 timeout。配置和本次期限变化原子提交，校验失败不产生部分更新。

E2B connect 与 Gateway 共用生命周期核心能力，保持期限计算、暂停保留策略和受保护写入的一致性。Gateway 负责流量准入、触发条件和合并请求，不调用 E2B connect HTTP 接口。运行中续期异步执行；已暂停 Sandbox 的自动唤醒仍取决于已有唤醒配置。

## 背景

现有 Gateway 能在流量到达时唤醒允许自动恢复的 Sandbox，并为自动暂停场景重新设置暂停期限。它尚不在 Running 状态下根据持续流量延长期限，因此用户正在访问或接收流式输出时仍可能触发时间到期。

现有 connect 已包含运行中延长期限、暂停后恢复、恢复时长保护和暂停保留时间计算。直接调用底层 Resume 不会为已经 Running 的 Sandbox 续期；另写一套期限规则则会增加行为分歧和维护负担。复用 connect 的核心能力能够让两种入口采用同一套生命周期语义。

目标是让显式选择此功能的用户减少主动发送 connect 保活的需要。功能只响应经过 Gateway 的实际流量，不承诺单凭连接存续或后台计算持续运行就一直保活，也不取代既有暂停、删除和其他生命周期规则。

## 设计终态

### 配置协议与持久化

提供两个扩展参数，适用于现有 v1/v2 create、v1/v2 connect 和 timeout 入口；原生路径与自定义路径行为一致。

| 参数 | create metadata | connect / timeout header |
| --- | --- | --- |
| 续期阈值 H | `e2b.agents.kruise.io/auto-renew-threshold` | `X-E2B-Kruise-Auto-Renew-Threshold` |
| 目标时长 R | `e2b.agents.kruise.io/auto-renew-target` | `X-E2B-Kruise-Auto-Renew-Target` |

阈值同时承担开关功能。正值开启；合法零值（如 `0`、`0s`、`0%`）关闭。关闭时删除阈值 annotation，不保存零值或空字符串，目标时长继续保留。缺少阈值的对象自然保持关闭，不另设布尔开关。

阈值接受 Go duration 字符串或非负十进制百分比，例如 `1m`、`500ms`、`12.5%`。百分比只在收到该字段时，按照本次接口经过默认值填充和校验的 timeout 计算一次。计算基准不包含暂停恢复的 300 秒保护下限，也不是当前剩余时间或续期目标。后续不带阈值扩展的调用不重新计算已保存的阈值。

目标仅接受换算后为整秒且至少 2 秒的 duration，例如 `2s`、`1m30s`、`1.5m`；不接受 `1s`、`1.5s`、零、百分比或 `forever`。目标不能超过服务端 timeout 上限。该下限适用于显式目标及 create 默认目标，也适用于关闭时显式提供的目标。阈值允许亚秒，沿用 duration 的纳秒精度，正阈值换算后至少为 `2ns`；百分比计算结果向下取至纳秒，正数换算后不足 `2ns` 时拒绝，不能因取整而关闭续期。输入负数、非法单位、非有限数值、溢出或无法安全表示的值均拒绝。

生命周期截止时间沿用现有 UTC 整秒向下截断。选择 R 至少 2 秒，是为了排除 R=`1s` 与亚秒阈值组合在到期前始终无法产生更晚整秒期限的配置，同时保留现有时间规范化和主动改期语义。正 H 至少 `2ns` 则排除了严格阈值窗口 `0 < E-t < 1ns` 中不存在可表示剩余时间的另一边界。对于整秒 E、任意合法 H 和 R，在 `0 < E-t < min(H, 1s)` 内存在可表示的时间点，且计算的续期目标严格晚于 E；这只保证表示精度下存在可延长的机会，不保证时钟采样或异步写入一定赶上该窗口。

metadata 中的值必须是字符串。扩展值去除首尾空白后不得为空；header 名称按 HTTP 规则大小写不敏感，每个参数只允许单值，重复 header 或逗号拼接多值均拒绝。百分比使用普通十进制写法，不接受科学计数法。duration 沿用 Go 单位，不额外支持 `d`。显式提供的非法字段始终使整次请求失败，即使阈值同时设为零。

服务端将有效阈值与目标分别写入系统 annotation `agents.kruise.io/traffic-renewal-threshold`、`agents.kruise.io/traffic-renewal-target`，值均为规范化的绝对 duration 字符串，不持久化百分比。外部 metadata 不能直接写入这些系统键；公开扩展键作为功能参数消费，不承诺普通 metadata 原样回显，不增加响应字段。Gateway 只信任经过 API 处理的系统记录，不从创建时间和当前截止时间反推原始 timeout。

开启或修改一个仍开启的配置时，合并后的 H、R 须分别满足上述时长规则，且必须满足 `0 < H < R`。目标不必等于本次 timeout，阈值也不必小于本次 timeout；百分比不另设 100% 上限，是否可接受由换算后的组合决定。

### create 的默认值与前置校验

create 先按既有规则确定本次 timeout：缺省或零使用 300 秒，再校验既有最小值 30 秒及服务端上限。随后完成百分比换算、目标默认值填充和续期组合校验。不能在 timeout 尚未填充默认值时，把百分比错误地换算为零。全部请求级校验通过后才能进入 Claim 或 Clone；非法续期参数不会先领取、创建或修改 Sandbox。

create 未传阈值则关闭；未传目标则将本次有效 timeout 保存为 R，即使关闭也保存目标。只传目标允许预配置，但不自动开启。Claim 和 Clone 都只采用本次请求的选择：清除候选、模板或 checkpoint 中可能残留的阈值，按本次请求写入或保持缺失，并重新确定目标；不继承上一交付的续期配置。

auto-pause、auto-resume 与 never-timeout 的既有合法组合继续允许。续期不隐式开启 auto-pause 或 auto-resume。never-timeout 仍保持没有生命周期截止时间；配置可以保存，但不触发续期，也不把对象转换为计时 Sandbox。

### connect / timeout 的配置更新与原子性

两个 header 分别按字段修改：未提供的字段保持现值，都未提供则配置完全不变。只改目标不重算阈值，只改阈值不重设目标；目标缺省为 timeout 的规则只在 create 生效。历史对象没有保存目标时，首次开启必须显式提供目标；不猜测历史创建 timeout。历史对象仅设置目标也允许保持关闭。

请求体 timeout 决定本次主动改期，扩展字段决定后续自动续期，两者独立。connect 保持只延长有效截止时间，timeout 保持主动覆盖、允许缩短的语义。v1 connect 和 timeout 保留既有必填与范围规则；v2 connect 缺省 timeout 使用 300 秒。暂停 connect 的百分比仍按请求 timeout、而非恢复下限计算。

鉴权、所属用户和资源身份验证沿用现有 API 边界。首次产生资源变更前，完成输入合法性、合并后续期配置、当前操作资格及期限计算的校验。缺少扩展的请求不新增对既有续期配置的校验或回填；显式关闭可以删除异常阈值，不因保留的旧目标异常而阻止关闭，但显式传入的新目标仍须合法。

新配置和此次期限在同一个 Sandbox 对象的受版本条件保护的写入中原子提交，删除阈值也是该次提交的一部分。不得先保存配置、再修改期限或反过来。connect 判定无需延长、timeout 的期限值未变，以及 never-timeout 不产生期限时，仍必须接受合法配置更新；即使最终没有字段变化，也不能仅凭旧缓存宣告请求已满足。

并发冲突后重新读取同一交付的状态，只合并本次明确提供的字段，再检查组合和操作资格；不能重新提交旧快照覆盖别人修改的字段。配置和期限要么按这次合法组合一起提交，要么此次尝试都不生效。同字段的并发更新以实际接受的提交顺序为准，不保证请求到达顺序。

初次校验发现新扩展或其合并配置非法时返回 400；已通过前置校验、但并发变更使其不再合法或无法在有界重试内提交时返回新增扩展的 409 冲突。原有鉴权、查找及其他错误保持既有类别与映射，不把后端内部细节暴露给用户。timeout 外层不得把这些新增 400/409 错误改成 500；不带扩展的旧请求保持既有映射。

### 暂停恢复的提交边界

暂停 connect 在任何恢复变更前完成上述校验。接受恢复的首次写入将新续期配置、恢复保护期限和 `paused=false` 一起提交。计时 Sandbox 的恢复时长沿用 `max(请求 timeout, 300 秒)`；这不改写保存的 H、R，never-timeout 仍不产生期限。并发调用中已经由其他请求解除暂停时，不重放旧的暂停状态或覆盖胜方期限；按当前可接受的恢复或运行状态，原子处理本次字段更新和只延长规则，保持已有同向恢复等待语义。

等待 Sandbox Ready 是提交之后的生命周期过程，不属于可回滚的存储事务。恢复完成后的补充延期仅在本次恢复仍有效、未被后续配置修改、显式改期或暂停/恢复取代时执行；它不重新提交旧配置，并继续遵守当前身份、状态和只延长条件。

参数校验拒绝发生在首次提交之前，不先唤醒再报参数错误。首次提交成功后，恢复等待失败、请求取消或后续步骤失败不会回滚已提交的配置与期限，也不能把已接受的配置重新报告为参数校验失败。后端写入响应丢失时结果可能未确认，不能声称肯定未生效；重新观察实际状态后再判断，不能盲目补偿覆盖并发更新。

### 流量与触发条件

只有按现有 Gateway 规则获得准入并定位到具体 Sandbox 的请求才产生续期资格。其新请求到达、非空请求数据及非空响应数据均可触发检查，包括正常 HTTP、SSE 和 WebSocket。沿用已有流级鉴权语义，不逐数据块重新认证；续期始终绑定该流最初获得准入的 Sandbox 身份。

流量按非空字节事件计算，不解析业务内容。因此 SSE 心跳、WebSocket 心跳也属于流量；空回调、连接仍打开、连接关闭事件以及 Gateway 自己生成的拒绝响应不算流量。经过其他入口或直接访问 Pod 的流量不在范围内，Sandbox 主动访问外部的流量也不在范围内。

有效截止时间 E 沿用 connect 的选择：存在 `pauseTime` 时使用它，否则使用 `shutdownTime`。Running 且尚未要求暂停、未进入删除的同一 Sandbox，持有有效的 H、R 且满足 `0 < E - 当前时间 < H` 时可发起续期。恰好等于阈值不续期；已经到期时不通过普通续期抢救，后续按既有生命周期执行。首次流量检查与重试都要尊重当前状态和当前记录。

没有流量时不进行周期性保活。事件检查使用本地缓存；不为每个数据块发管理请求或 Kubernetes 请求，不保留或记录数据内容。

### 共用 connect 核心能力

共用范围是协议无关的生命周期计算和执行能力：有效期限选择、按时长计算期限、自动暂停与销毁模式、暂停保留时间、恢复最短时长、只延长规则，以及配置和期限的受保护持久化。将需要共享的能力放在 Gateway 可依赖的中立边界，现有 connect 通过其 Manager/Infra 路径调用；共享代码不依赖 E2B handler、HTTP 模型或状态码，不扩大 Gateway 对 API/Manager 包的遗留依赖。

API 层负责 API Key、所属用户、metadata/header 解析、默认值和百分比换算、协议校验及 E2B 响应。Manager 经中立 Infra 能力执行生命周期用例；具体后端负责条件写、同一交付核验和冲突重试。Gateway 负责其现有流量准入、已保存策略的检查、异步任务及本地请求合并。Sandbox Controller 继续负责观察期限并执行暂停/删除，不引入对 API 或 Manager 的反向依赖。

调用核心能力时区分显式 connect、流量续期和获准的流量唤醒：显式 connect 按上述扩展协议更新配置并保留主动改期规则；流量续期只允许更新 Running Sandbox 的期限，不允许恢复暂停状态；流量唤醒只有通过现有自动唤醒条件才允许恢复。Gateway 不构造管理 API 凭证或发起 E2B connect HTTP 请求。

### 运行中续期

一次续期首次计算目标时固定基准时间 t 和本次配置，目标有效截止时间为 `t + R` 向下截断至 UTC 整秒；相对 t 的目标时长大于 `R-1s` 且不超过 R。若规范化后的目标不晚于当前有效截止时间，本次不写入，后续合格流量可重新检查。重试同一次工作不不断推进 t，不把目标计算为旧截止时间再加 R。若重试发现策略已经改变或关闭，终止旧配置下的工作，后续新流量按新配置触发。

对于自动销毁模式，只延长 `shutdownTime`，不产生 `pauseTime`。对于自动暂停模式，延长 `pauseTime`，并按 connect 的同一暂停保留策略计算配套 `shutdownTime`。暂停保留时长独立于 R；缺失或非法的保留策略沿用 connect 的默认和诊断规则，仅在实际接受的期限更新中写入必要的默认值。冲突重试采用当前模式与保留策略，不覆盖较新的策略。

“只延长”约束的是有效生命周期截止时间，不能把暂停后的保留窗口误当作 Running 生命周期。若其他请求已经把有效期限延长到目标之后，本次不缩短它。普通续期不使用恢复过程的最短 5 分钟规则，使用当前保存的 R。

显式 timeout 仍可缩短当前期限；没有扩展时 H、R 不变，后续合格流量可能再次续期。需要缩短期限并禁止后续续期时，可在同一次 timeout 请求中传零阈值，原子删除阈值并修改期限。关闭不撤销在它之前已经提交的续期；connect 的只延长规则也不会因关闭而变成允许缩短。

### 与自动唤醒的关系

续期与自动唤醒是独立选择。仅开启续期不会使 Paused Sandbox 自动恢复，也不会绕过 Gateway 的唤醒总开关。Running Sandbox 的续期不依赖唤醒总开关。

两者都开启且通过既有唤醒条件时，共用 connect 核心能力以保存的 R 发起恢复。计时 Sandbox 沿用现有恢复保护，将本次恢复时长取为 `max(R, 300 秒)`；这不改写保存的 H、R。此时恢复时长由 R 决定，不采用唤醒规则 `AutoPausePolicy.Resume.OnIngressTraffic.PauseTimeout`。解除暂停与初始新期限必须在同一次受保护状态更新中完成，避免旧期限在恢复途中生效。恢复成功后的补充延期遵守上述恢复有效性和只延长条件；流量等到 Sandbox Ready、路由可用后再转发。

自动暂停模式重新设置暂停期限和对应的暂停保留窗口；自动销毁模式只重新设置销毁期限。无期限对象仍保持无期限。未开启续期的 Sandbox 继续使用已有唤醒行为。恢复失败、等待超时或请求取消继续沿用现有唤醒的返回和取消语义。

### 并发、身份与失败

本功能涉及的 API 配置更新、流量续期及唤醒状态变更，都在执行前和每次条件写重试中核对当前对象的 namespace/name、UID 和公开 Sandbox ID，确保仍为最初获得授权或准入的交付，不操作同名替代对象。普通续期还要重新核对有效配置、Running 状态、暂停意图、删除状态和阈值；身份变化、对象消失、策略变化或移除、已要求暂停或删除时终止旧工作，绝不写 `paused=false`。获准的唤醒则重新核对当前唤醒资格、删除状态和期限策略，保持既有并发恢复的幂等语义。

后端写入采用版本条件，只修改本次需要更新的期限和必要策略字段。Gateway informer 中被裁剪的模板等字段不得因更新而被擦除。发生冲突后重读并重新判断，不使用旧模式、旧身份或旧阈值判断强行覆盖新状态；本次新增流量续期使用缓存和条件写实现，不新增 APIReader 直读依赖。

同一 Gateway 对同一 Sandbox UID 合并并发触发，工作量和等待队列有界。多个 Gateway 可以竞争，但以存储中的最新对象和条件写决定结果，重试时再次判断阈值和目标是否仍需要延长。不会因 N 个并发流量事件而累计增加 N 个 R，也不引入跨 Gateway 分布式锁。短时长的整秒规范化、缓存滞后或配置接近边界不能造成无界重试或逐数据块写入。

运行中续期异步执行，不阻塞数据转发。失败时记录可定位的结构化错误，不改变正在服务的响应或断开流；后续流量可以在退避后再次触发。一次工作及其冲突重试必须有截止时间；无新流量时不形成无限后台重试。网络返回不确定时不把本地期限标成已成功，后续根据实际观察重新判断；同一次工作重试仍使用固定目标，避免重复延长。

流结束后不再产生新触发；已经接收的有界续期可完成，成功写入不因客户端断开而回滚。后台工作不持有已销毁流的 Envoy 回调或数据缓冲；Gateway 停止时取消尚未完成的工作。日志不得包含访问凭证或业务数据，本次不新增 Prometheus 指标。

### 兼容性与能力边界

没有阈值的对象保持关闭，不自动迁移或启用历史对象。持久化策略缺失、非法或不可安全表示时 Gateway 跳过续期，对异常值记录诊断，不猜测或回填。新 API 与支持该能力的 Gateway 配合才能提供完整能力：旧 API 不识别这些扩展，旧 Gateway 不执行续期；混合版本期间不能保证配置更新被识别或任意流量路径均触发续期。升级、回滚均不将无期限对象转为计时对象。

本次复用既有 create/connect/timeout 入口，不增加独立配置接口、CRD spec 字段或模板级默认开关。暂停保留策略、自动唤醒准入和其他主动暂停规则保持各自职责。

新增扩展参数、系统 annotation 和共享生命周期核心属于仓库规则所指的新 API 和架构变更，实现交付须在 `docs/proposals/` 提交描述本设计的提案。

本功能延长生命周期期限，不改变访问令牌有效期、代理空闲超时、负载均衡连接限制或其他主动暂停规则。它不能阻止手动暂停/删除、探针驱动暂停、集群故障或已经发生的到期动作。接近到期时的突发流量和后端故障可能来不及续期；异步设计提供尽力续期，不承诺每一次合格流量都能阻止到期。

### 可观察验收结果

| 场景 | 结果 |
| --- | --- |
| create 的 timeout 缺省，阈值 `10%`，目标缺省 | 保存 H=`30s`、R=`5m` |
| create timeout=600，阈值 `10%`，目标 `5m` | 保存 H=`1m`、R=`5m` |
| create timeout=600，阈值 `10%`，目标 `30s` | 400；不进入 Claim/Clone，不创建或领取 Sandbox |
| create timeout=30，阈值 `500ms`，目标 `1s`，或未传阈值但显式目标为 `1s` | 400；不进入 Claim/Clone，不创建或领取 Sandbox |
| create 未传阈值，候选对象带有旧阈值 | 清除旧阈值保持关闭；目标按本次 create 确定 |
| H=`500ms`、R=`2s`，E=`12:00:10Z`，t=`12:00:09.600Z` | 目标为 `12:00:11Z`；无竞争且提交及时成功时，有效期限延长 1 秒，自动暂停模式按同一保留策略配套调整 shutdownTime |
| create timeout=30，目标 `2s`，阈值 `1ns` 或 `0.000000005%` | 400；后者向下取至纳秒后为 `1ns`，不进入 Claim/Clone；`2ns` 或换算后至少 `2ns` 的正阈值可通过本项校验 |
| H=`2ns`、R=`2s`，整秒 E | t=E-2ns 时不续期；t=E-1ns 时满足触发条件且规范化目标为 E+1 秒 |
| H=`500ms`、R=`2s`，当前时间等于或晚于 E | 不通过普通续期抢救；最小目标不改变到期规则 |
| H=`1m`、R=`10m`，剩余 60 秒时有流量 | 不更新期限 |
| H=`1m`、R=`10m`，剩余 59 秒时有新请求或流内数据 | 异步尝试将有效期限延长至本次计算时间加 10 分钟 |
| 原 R=`10m`；connect timeout=1200，只传阈值 `20%` | H 改为 `4m`，R 保持原值；本次 connect 按 1200 秒和只延长规则改期 |
| 原 R=`10m`；计时 Sandbox 的 Paused connect timeout=30，只传阈值 `10%` | 保存 H=`3s`，R 不变；恢复保护时长至少 300 秒 |
| connect 无需延长，但传入合法的新目标 | 期限不缩短，新目标仍被保存 |
| timeout 请求同时缩短期限并传零阈值 | 同次提交修改期限并删除阈值；后提交的旧续期工作不能越过关闭 |
| connect / timeout 同时提交目标 `1s` 和零阈值，包括 Paused connect | 400；既不关闭续期，也不修改期限或先唤醒 |
| 原 H=`1m`、R=`10m`；并发请求分别改 H=`8m` 和 R=`5m`，均通过首次校验 | 一个先提交，另一个重校验后返回 409；不出现 H=`8m`、R=`5m` 的非法组合，失败请求的改期也不生效 |
| 只有下行 SSE 数据或 WebSocket 心跳持续经过 Gateway | 与新请求采用相同阈值和续期规则 |
| 连接一直打开但没有数据，或命令一直计算但不输出 | 不因连接存在而续期 |
| 同时有大量流量命中多个 Gateway | 续期不累加为多个 R，已接受的更晚有效期限不被缩短 |
| H=`500ms`、R=`2s`，已暂停且续期与流量唤醒都开启 | 恢复时至少设置 300 秒；R 仍为 `2s`，后续 Running 续期按整秒向下截断和 R 计算 |
| 续期任务排队期间对象已要求暂停，或同名对象 UID 已替换 | 该任务不恢复暂停、不写新对象 |
| 写入发生冲突、超时或结果不确定 | 业务流保持现有转发行为，不虚报续期成功，不无限重试 |
| Paused connect 初次提交成功，随后恢复等待失败 | 新配置与保护期限都已提交，不回滚；失败不意味着对象未发生变化 |
| 自动暂停与自动销毁两种模式 | 分别保持原模式，暂停保留时长不被原始 timeout 替换 |
| Gateway 读到构造的 H=`500ms`、R=`1s` 记录 | 按非法持久化策略跳过续期并诊断，不猜测或回填 |
| 历史对象没有目标，只传正阈值要求开启 | 400，要求显式提供目标；不猜测原创建 timeout |
| 没有阈值，或对象为 never-timeout | 不产生自动续期行为 |
