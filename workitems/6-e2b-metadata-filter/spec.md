# E2B Sandbox 响应中过滤内部注解

## 对外行为

在 E2B 将 Sandbox 转成响应对象时，按完整键过滤内部指纹。首批建议纳入以下两个 API 常量，待用户确认旧键范围。

| 注解（前缀均为 `sandbox.agents.kruise.io/`） | 用途 |
| --- | --- |
| `hash-immutable-part` | 控制器当前使用的模板指纹 |
| `hash-without-image-resources` | 旧版指纹，API 已标记废弃，历史对象可能保留 |

创建（含克隆）、连接、详情和列表共用此规则。E2B 为兼容旧数据还会读取标签，同名键从这两个来源进入响应时均应过滤。同前缀的普通业务键照常返回，注解覆盖同名普通标签的顺序照旧。

## 作用范围和验收

仅在组装响应 metadata 时应用这份键清单。已有的保留前缀规则、显式返回的 claim method、按条件返回的 Pod IP 和服务端生成的资源标识继续生效。控制器读写、claim 注解透传、创建请求校验以及列表查询条件沿用各自的现有规则。

给一个 Sandbox 同时设置内部指纹、普通业务注解和兼容标签，响应中应只从这些键里剔除清单中的键，原始对象仍含指纹。再加入一个指纹名带额外后缀的普通键，验证按完整键匹配。更新清单时所有返回 Sandbox 的接口共用同一处定义。
