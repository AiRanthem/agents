# 修复 Checkpoint 终态反复重试并处理快照与自动休眠的竞态

用户报告了一次 filesystem 快照失败。源 Pod 在快照发起时存在。后端连续两次因实例状态拒绝快照，下一次调谐前 Sandbox 已自动休眠并删除 Pod。最终状态只显示 `Pod Not Found`。同一时间，多个命名空间的终态 Checkpoint 持续以相同错误占用队列。事件经过与源码核验见[排查记录](context.md)。

## 研发范围与验收

1. 消除终态 Checkpoint 在 common control 下由 `not implemented` 引起的无限错误重试。在含存量终态对象和新建快照的场景中，验证重复错误停止、新请求能够继续推进，以及需要按 TTL 回收的对象仍按约定处理。
2. 给出采用已有修复的版本决策。核对组件所带控制器镜像，按控制模式和快照内容核查存量对象的状态、完成时间、TTL 和恢复引用，说明哪些对象应保留、是否需要清理及依据。尤其要验证已成功的 filesystem 快照落入 common control 后的状态变化。
3. 明确后端暂时拒绝创建快照时的重试条件、间隔上限与结束条件。在唤醒后立即请求快照的场景中，分别验证 Pod 仍可用、以及重试前已自动休眠并删除 Pod 的结果。对后一种情况给出可区分的失败原因或诊断证据，让调用者能够还原首次拒绝与后续删除的先后顺序。

本次交付为缺陷登记。升级目标、退避参数、快照与休眠的优先顺序以及存量清理范围均待研发评估。源码变更、组件发布和集群操作由后续授权推进。
