# 用户决定

2026-11-27，用户了解现场时序和两个方案后选择「A」：自动休眠按时启动。用户快照可在原 Pod 可用期间重试，等待快照不会延后自动休眠。

用户随后明确要求「休眠失败的原因不能再报告 Pod not found」，以免误以为 Pod 从未存在。本次现场失败的是用户快照，自动休眠按时执行。若另一场景中休眠确因其自身所需的快照失败，则休眠结果也应传达该步骤及已知原因。[设计中的可观察结果](spec.md#自动休眠与快照各自的结果)

用户随后提出「只看 403 就行，不用识别那么细，可以考虑把 api 输出放到状态或者事件里」。设计稿 v3 采用 ACS 创建接口的 HTTP 403 作为短重试条件，状态保存可读的后端答复摘要，Warning Event 辅助排障。30 秒窗口和 5 秒间隔是设计作者给出的参数。整稿待用户确认。
