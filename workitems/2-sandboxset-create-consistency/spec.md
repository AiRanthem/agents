# 摘要

手动创建 SandboxSet 后立即调用 E2B create，可能因 informer 传播延迟而被误判为模板未找到。对使用 `spec.template` 内嵌模板的独立 SandboxSet，本设计将等待集中在 `cache.PickSandboxSet`：命中立即返回，未命中时只读 informer，最多等待 5 秒。保留现有上层接口、流程和错误映射，接受共用查询调用方在未命中时增加同样的等待延迟。

# 背景

E2B 创建入口通过 `HasTemplate` 判断是否进入 claim；Manager 在 claim 前再次判断模板是否存在；冷启动构造 Sandbox 时也通过 `PickSandboxSet` 取得 SandboxSet。当前这条底层查询在缓存未命中时立即失败，因而外部 Kubernetes 创建成功与本地 informer 可见之间的短窗口会变成用户可见的 template not found。

这些检查共享同一个 informer 查询入口。在该入口容忍短暂未命中，可以覆盖原问题的多个调用点，并保持各层现有职责。Informer 的初始同步完成并不保证外部新写入立即可见；有限等待仅提供传播窗口内的容忍能力。

# 设计终态

## 范围与职责

本项的功能与验收范围为 `spec.template` 内嵌模板的独立 SandboxSet。有限等待由 `cache.PickSandboxSet` 统一提供，保留其现有参数和返回接口。上层继续按原有结果选择 claim、checkpoint clone 或失败路径，不引入跨层等待编排或新的 HTTP 错误映射。

共享查询方法仍供现有调用方使用，其等待行为不按调用来源另设开关。模板 GET、模板删除判定以及 claim 内的查询在未命中时也可能等待；原有权限、返回模型、匹配规则和处理流程保持一致。其他缓存 Get/List 方法不因此增加等待。

`spec.templateRef` 的引用解析、等待及相关一致性保证不在本项范围内。共享查询行为对现有调用方生效，不代表为 Ref 场景提供新的专项能力。

## 单次查询行为

每次调用先读取 informer 缓存，命中时立即返回。首次读取确认为未命中时，允许在该次调用内继续观察缓存，等待窗口最多 5 秒；对象可见后立即返回，不固定睡满整个窗口。

同一次调用的后续观察不能重新开启或延长窗口。父 context 取消或有更早截止时间时，遵守父 context，停止等待并保留其取消或超时原因。5 秒是该次查询的等待上限；不同调用分别计算，不建立跨层共享预算，也不替代现有创建、claim 或就绪等待期限。

查询必须区分正常的缓存未命中与读取错误。仅未命中参与等待；其他读取错误立即返回。自身 5 秒窗口结束仍未命中时，沿用现有未命中失败语义，由原调用方按既有逻辑处理。等待结束不是 API Server 中资源不存在的证明。

## 读取与并发约束

模板查询和等待全程只读 informer。禁止使用 `APIReader`，包括任何经复用 helper 隐式发起的实时回源。等待不创建、修改或删除 Kubernetes 资源，也不向 informer 人工注入查询结果。

所有观察保留原有 namespace、label selector 和名称索引的匹配规则。空 namespace 仍保持原有跨 namespace 查询含义；不将其替换为默认 namespace，也不扩张 informer 已配置的可见范围。缓存对象继续作为共享只读状态。

并发调用各自持有有效期和取消语义。一个调用取消不能使另一个仍有效的调用提前结束；晚到调用不能继承早到调用已经消耗的等待窗口。内部是否复用瞬时缓存读取结果不改变这一约束。

## 可观察结果与接受的限制

- 模板已可见：立即查到并继续现有创建流程，最终创建结果仍由库存、配额、就绪和运行时等既有流程决定。
- 模板在窗口内才可见：同次查询返回该对象，避免首次未命中直接引发模板未找到。
- 模板始终不可见：最多等待 5 秒后按现有未命中路径结束。仅 checkpoint 可见的创建可能先增加这一等待，再走既有 clone 流程；两者仍未可见时，保留原有未找到结果。
- 调用取消、提前到期或发生读取错误：终止该次等待，cache 保留对应原因，上层 HTTP 映射保持原状。
- 多处查询：每处独立适用同一规则，整个创建的新增等待不能被表述为统一最多 5 秒；已观察到且持续可见的对象在后续检查中会立即命中。

本设计容忍有限窗口内的 informer 传播延迟，不消除任意长的同步延迟，不建立资源更新或删除的强一致保证，也不改变管理员跨 namespace 同名对象的既有匹配语义。后续若需更强保证，应在新的需求和授权下重新评估读取合同；本项始终遵守禁止 `APIReader` 的约束。
