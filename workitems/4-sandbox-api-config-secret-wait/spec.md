# 摘要

sandbox-api 等待配置 Secret 时无法完成 Pod 就绪，可能阻塞依赖 Ready 判断完成的发布系统。增加启动参数 `--ready-before-config`，默认关闭，仅在设置了 `--secret-config` 时生效。开启后，其他必要启动条件满足即可先完成探针就绪。控制 API 在配置和后续初始化完成前拒绝业务请求，等待配置 Secret 时允许返回任意 HTTP 错误码。Envoy 的 Sandbox 数据面按已有路由处理流量。配置补齐后，同一进程自动开放业务。默认启动和运行后的配置热更新保留既有行为。

# 背景

配置 Secret 的观察与配置生效已有独立机制。当前启动必须先等到所有相关组件确认初始配置，之后才启动 Manager、HTTP 与相关监听。这能防止未配置实例处理业务，但也使配置等待成为 Pod Ready 和发布完成的前置条件。

用户需要在部署阶段允许实例先 Ready，再完成配置。由此，开启新模式后的 Ready 表示进程的受控服务入口已就绪，业务可用性由独立的初始配置及运行时门禁决定。发布系统可以继续推进。控制 API 在初始化期间拒绝业务请求，避免访问未初始化的认证、存储或配额组件。

该取舍允许 Service 将流量发送到待配置实例，也允许滚动更新据 Ready 推进旧副本替换。因此新模式必须显式开启，不能成为既有部署的默认行为。

# 设计终态

## 开关与适用范围

新增布尔启动参数 `--ready-before-config`，默认值为 `false`。它是进程启动配置，不能依赖尚未就绪的配置 Secret 提供，也不通过 Secret 热更新改变。

| 启动配置 | 行为 |
| --- | --- |
| 参数未设置或为 `false` | 保留现有行为：初始配置确认后才完成后续启动，不提前开放监听以满足就绪 |
| 参数为 `true`，且 `--secret-config` 非空 | 启用提前 Ready，控制 API 暂停业务处理 |
| 参数为 `true`，但 `--secret-config` 为空 | 保留静态 flag/env 配置路径的现有行为，不扩大本项范围 |

开关只影响单个 sandbox-api 实例的首次启动。配置来源、Secret 的引用格式与数据要求、鉴权模式、存储选择和配额策略保持既有合同。

## 就绪与业务激活

开启新模式后，启动在可观察行为上分为以下阶段：

1. **必要启动条件尚未满足**：继续完成静态参数检查、必要的固定安全配置和监听准备。此时不承诺 Ready；已有致命启动错误仍使进程失败退出。
2. **服务入口已就绪、业务尚未激活**：现有探针所需的受控监听已可用，健康检查与现有观测接口正常工作。初始配置是否完成不再阻塞探针就绪；其他容器与 Kubernetes 条件正常时，Pod 可达到 `2/2 Ready`。控制 API 拒绝业务请求，Envoy 按下文的路由规则处理 Sandbox 流量。
3. **业务已激活**：相关组件已完成初始配置确认，并完成后续运行时初始化，包括既有缓存与初始路由处理要求。同一进程解除控制 API 的业务门禁，进入正常服务。

“Secret 对象存在”不足以解除门禁。只有配置观察、解析及相关组件的初次确认成功，并且服务业务所需的后续初始化完成，才能激活业务。初始配置一开始有效时也遵守这一条件，不增加固定等待时间。

探针就绪必须覆盖实际使用的入口。现有双容器编排包含 controller 的 7789 TCP 检查与 Envoy 的 7788 TCP 检查；仅提前开放独立 metrics 端口不能实现该编排下的目标。已有监听地址、探针入口及传输安全要求继续有效，不能通过弱化必要的证书校验或开放不受控入口达成 Ready。实际编排的其他就绪条件不由进程强制覆盖。

## 待配置期间的请求行为

控制 API 的 native 与 customized 业务端点在激活前拒绝请求，包括经 Envoy 转到控制 API 的请求。等待配置 Secret 期间允许任何 HTTP 错误码，只要请求未进入业务处理。准入检查返回 `503`；此前的协议校验也可以返回错误，例如 tracing 拒绝无效请求 ID 时返回 `400`。控制 API 沿用既有错误格式并保护凭据和后端信息。

控制 API 请求直接失败，不排队重放，不进入依赖配置的鉴权、存储、配额或其他业务处理。关闭鉴权时仍须拒绝业务。Envoy 的 Sandbox 数据面独立于这项控制面门禁。待配置时可接流，没有路由时沿用缺路由错误，已有 Running 路由时可以转发。

现有控制面健康与观测端点是业务门禁的例外，包括适用监听上的 `/health`、`/metrics` 和 `/kruise/api/health`。端点按已有规则分类。Sandbox 业务域名或业务路径下的 `/health` 按 Sandbox 路由处理。

业务激活后，请求恢复现有的鉴权、权限、错误映射和路由行为。本项不增加新的业务 API 或修改正常服务时的成功响应。

## 配置观察与失败结果

继续复用按目标 namespace/name 限定的独立配置 informer，以及相关组件的初始配置确认边界。配置观察与业务门禁的生命周期不能依赖尚未激活的业务处理，不新增直接回源读取或另设配置轮询流程。

服务入口已就绪后，控制 API 的行为如下。Envoy 的 Sandbox 路由独立生效。

| 情况 | 提前 Ready 模式的结果 |
| --- | --- |
| Secret 尚不存在或首次确认前被删除 | 保持 Ready，控制 API 拒绝业务并返回错误，继续观察后续创建或修改 |
| Secret 形状或配置值无效 | 保持 Ready，控制 API 拒绝业务并返回错误，等待有效修正 |
| 首次配置应用或后端验证尚未成功 | 保持 Ready，控制 API 拒绝业务并返回错误，沿用既有配置重试与确认机制 |
| 配置观察发生读取、连接或同步故障 | 保持业务关闭，观察器按既有恢复机制继续工作，不以陈旧或默认凭据放行业务 |
| 初始配置确认且后续初始化完成 | 在原进程中激活业务，无需因最初缺失而重启 |
| 静态参数、安全配置、必要证书或监听绑定等致命错误 | 保留原有失败语义，退出进程；不能长期伪装为健康的待配置实例 |

观察源在初始化完成前意外结束，也不能解除业务门禁，应按既有初始化失败语义终止。本项不改变配置组件之间没有全局事务的既有限制，不额外承诺各组件确认来自同一 Secret 版本。

## 生命周期与责任边界

启动协调者区分探针就绪与控制 API 业务激活。API 层负责本实例的准入和 HTTP 错误映射，Manager 负责业务运行时与后台任务，proxy 按已有路由转发 Sandbox 数据面流量。

依赖有效配置的后台维护、成员加入及业务运行时激活保留各自的配置前提。不能仅删除前台等待、提前运行全部后台工作，再依赖 HTTP 门禁保护未初始化存储。探针或受控传输入口提前启动不代表实例已经承担正常成员和业务职责；后续业务激活仍须完成原有初始路由处理。

配置在后台生效可产生既有配置初始化所需的持久化效果，业务门禁不禁止这些效果；待配置的控制 API 请求不能绕过初始化前提执行业务。配置重试仍保留既有确认、失败与未决意图语义。

从待配置进入正常服务时，已开放入口保持连续可用，不因转换重复绑定端口或重复启动组件。收到终止信号或 context 取消时停止配置等待及恢复工作，按有效退出预算停止已经启动的组件；不能等待从未启动的后台 worker，也不能在终止后因晚到配置确认重新开放业务。配置完成后的其他必要初始化若发生致命错误，应终止进程，不能无限停留在表面 Ready 的状态。

## 超时、兼容与接受的限制

进程不读取、复制或推算 startup probe 的超时配置，也不设置配置等待的进程内总期限。既有单次观察或后端操作的超时与恢复机制保持不变。

默认模式继续由外部 startup probe 约束原有启动过程。提前 Ready 模式下，startup probe 限制的是服务入口启动；其成功后不再限制初始配置等待。配置持续缺失或无效时，可以持续表现为 Ready 且控制 API 拒绝业务请求。

业务激活是首次启动的一次性边界。正常运行后，Secret 删除、无效更新或重载失败继续沿用既有最后有效配置和组件重载行为，不因本开关重新进入初始待配置状态。重启的新实例重新执行相应启动模式。

开启新模式不承诺配置未就绪期间的业务可用性，不增加 Service 流量隔离或旧副本保留机制，也不保证所有发布系统都会通过：额外业务检查仍可能失败。只有依赖所支持探针与 Ready 的发布判定才会消除这一配置等待阻塞。要求业务可用后才能发布完成的部署应保留默认模式；如需提前 Ready 同时保证业务可用，应另行建立流量与发布合同。

本项不改变 runtime TLS、peer 安全或其他固定证书 Secret 的就绪要求，不新增配置监控指标、诊断 API 或发布系统旁路，不代替部署与现场验证。

## 可观察验收场景

- 默认模式，Secret 缺失：保持原有未完成启动状态；补齐有效配置后按正常流程启动。
- 提前 Ready 模式，Secret 持续缺失：在其他启动条件正常的双容器编排下，Pod 可达到 `2/2 Ready`，健康与观测接口可用，直连和经 Envoy 转到控制 API 的业务请求均被拒绝，任意 HTTP 错误码均满足要求。Envoy 的 Sandbox 请求按路由可用性处理。进程可以持续等待配置。
- 提前 Ready 模式，Secret 存在但无效或首次后端验证失败：不会错误开放鉴权、业务或配置相关维护。修正并完成初始化后，同一进程恢复正常服务。
- Secret 已有效但初始路由或其他必要运行时初始化尚未完成：控制 API 门禁继续返回 `503`，不能仅凭配置确认提前放行业务。
- 待配置或后续初始化期间收到终止信号：进程结束相应等待和已启动工作，晚到配置不能触发业务激活。
- 业务已激活后删除或无效修改 Secret：保留原有热更新失败处理；本开关不重新关闭已激活业务。
- 未设置 `--secret-config`，无论本开关值如何：静态 flag/env 路径保持原有行为。
