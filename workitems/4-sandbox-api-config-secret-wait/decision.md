# 当前决定

## 用户已明确的决定

1. **问题更正**：等待配置时 Pod `0/2 Ready` 会使部分发布系统卡住。用户于 2026-11-17 在本会话更正：“需求表达错误，现在等待的时候会出现 0/2 ready ，导致一些发布系统会卡住”。
2. **提前 Ready 与业务拒绝**：用户在本会话选择“Pod 先变成 2/2 Ready，配置完成前业务返回 503（会接入流量，也可能推进滚动替换）”。这批准了该方向及选择中说明的影响，不等于完整设计、业务可用性保证或源码实现批准。
3. **启动开关**：用户随后要求“这个需要一个开关控制启动时的行为”。开关应为进程启动配置，不受尚未就绪的配置 Secret 自身控制。

## 待批准的完整合同

开关名称、默认值、Secret 与静态来源的适用边界、初始配置错误分类、健康/业务/后台生命周期、同进程恢复和后续热更新行为，需与正式设计路径一并最终确认。当前建议和源码依据保存在 [context.md](context.md)。尚未编写 `spec.md`，没有独立评审结论。
