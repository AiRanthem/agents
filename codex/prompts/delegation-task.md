# Delegation and task context

Delegate substantive work when added coverage or parallel benefit outweighs startup, reading, verification and integration cost. Reuse sufficient current evidence or continue with a suitable existing executor first. Keep one owner for related investigation; do not split it by tool call or file, or create tasks to fill capacity. Dispatch worthwhile independent workstreams early. Handle trivial work, tightly coupled consequential reasoning and targeted primary-source checks directly. A missing fact, permission or tool is not solved by changing models.

State the expected result and acceptance criteria, the scope and target version, and the authorization and constraints. Give the executor an evidence index and identify the gap to close. Before dispatch, read the smallest set of originals that the parent and descendants are likely to use repeatedly. Include the relevant instructions, contract, stable diff and central code. Reuse current reads and leave specialist-only exploration to the executor.

## Context selection

- Prefer `fork_turns: "all"` for substantial shared context with the same model and effort and relevant history, when the host preserves the shared prefix, required roles and permissions. Read the shared originals before forking and append the child assignment without recopying them. The parent retains ownership of the full task.
- Use `fork_turns: "none"` for model or effort changes, unrelated history, independent review of a parent's work or unavailable full-context reuse. Supply sufficient original inputs and an evidence index. Parent reads alone do not transfer to clean children.

Record any fallback. Choose routing for the assignment regardless of potential cache hits and preload only relevant material. Cache reuse requires a matching rendered prefix and compatible request settings. Claim savings only from measured usage. Compare exposed cached and uncached input, cache writes where available, latency and total work. Identical file contents alone do not prove reuse.

Load only the inputs applicable to your role and mode. Reuse unchanged inputs already in context while honoring mandatory instruction reloads. Use summaries to locate originals and rely on complete contracts and the necessary primary sources for judgment. Before handoff, check the result against the assignment's acceptance criteria and fix any in-scope gaps you can resolve.

When explicitly selecting an Astra subagent, use the native `astra-delegate` role and pass the selected model and effort explicitly. Its persistent developer instructions reload the scoped policy after compaction; startup hook context alone is insufficient. If the host cannot select that role or provide equivalent persistent developer instructions, report that missing capability for the Astra assignment. Preserve any user-designated role and required review.
